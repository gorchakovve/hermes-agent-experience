# P-055. Autossh monitor port приняли за сломанный обратный SSH-маршрут

[English version](en/P-055.md)

**Статус доказательств:** частично подтверждено. Есть операционный урок и архивная ссылка на запись о техобслуживании; эта контрольная проверка не доказывает долгосрочную устойчивость обратного маршрута и не закрывает отдельный контекст fail2ban.

## Когда и в каких условиях
2026-05-31. Агенты использовали обратный доступ iMac↔VPS для диагностики; рядом существовали уроки про throttling autossh и fail2ban.

## Симптомы
Сообщение `remote port forwarding failed` приняли за поломку SSH endpoint для доступа VPS→iMac, хотя оно относилось к monitor port autossh.

## Разделение наблюдений и действий
Оператор разделил прямой SSH к VPS, настоящий обратный listener и monitor port; сделал резервную копию LaunchAgent, перевёл autossh на `-M 0`, оставил SSH keepalives и перезапустил только агент туннеля.

## Причинная гипотеза
Сбой был шумом механики monitor port; основной обратный маршрут в момент проверки работал.

## Что не сработало бы
Нельзя считать monitor port рабочим endpoint, менять основной SSH-маршрут или разбирать fail2ban без доказанного отказа основного пути.

## Что помогло
Помогло отделить служебный listener от monitor listener и убрать monitor port для этого LaunchAgent.

## Проверка результата
Нужный обратный listener сохранился; monitor listener исчез; пробный reverse SSH вернул ожидаемые user/host/cwd; связанные службы были active.

## Ограничения
Бессрочная устойчивость туннеля не доказана; уроки по fail2ban применимы только после отдельной проверки его участия.

## Основание
Основание: ограниченные по области записи Brain о техобслуживании, уроках и каноне, а также история git этой ветки документации. Сырые журналы, приватные пути, домены/IP, email, секреты и конфигурации намеренно не публикуются.
