# P-051. Hermes Desktop потерял рабочий VPS из-за зависшего локального туннеля

[English version](en/P-051.md)

**Статус доказательств:** подтверждено внутренней записью о техобслуживании от 2026-09-23. Исправление было точечным; эта проверка не доказывает долгосрочную устойчивость SSH-сеанса.

## Когда и в каких условиях
2026-09-23. Intel Hermes Desktop работал как удалённый интерфейс к рабочему Hermes на VPS через локальный SSH-проброс на loopback. Telegram, VPS Dashboard/Gateway и серверная часть рабочего контура проверялись отдельно.

## Симптомы
Desktop не подключался к серверной части. Локальный порт был открыт, поэтому симптом мог выглядеть как ошибка Desktop или авторизации, но старый SSH-сеанс отвечал отказом на проброшенный канал.

## Разделение наблюдений и действий
Hermes/оператор сначала проверил серверную часть на VPS: версию, Dashboard/Gateway, состояние API и Telegram. Затем отдельно проверил локально проброшенный API и журналы Desktop. Действие было одно: перезапустить только локальное задание launchd для туннеля и затем Desktop, чтобы приложение взяло новое соединение. Владелец не менял учётные данные; Talos/OpenClaw и proxy в этом ремонте не участвовали.

## Причинная гипотеза
Наиболее подтверждённая причина — зависший SSH-проброс между Desktop и VPS. Серверная часть и OAuth были исключены живыми проверками: API на VPS отвечал, а после перезапуска того же туннеля Desktop сразу увидел удалённую серверную часть.

## Что не сработало бы
Обновлять Desktop, менять OAuth, трогать обратный SSH-маршрут, xray/Gemini proxy или перезапускать службы VPS было бы лишним: отказ находился на участке между локальным портом и службой на VPS.

## Что помогло
Рабочий порядок был таким: проверить API на VPS напрямую; проверить локально проброшенный API; посмотреть свежую попытку Desktop; перезапустить только задание туннеля; затем перезапустить Desktop.

## Проверка результата
После ремонта API через туннель вернул здоровый VPS Hermes, Desktop записал готовность удалённой серверной части, а авторизованные WebSocket-проверки для событий и PTY открылись через локальный туннель.

## Ограничения
Desktop оставался совместимой, но не самой новой версией. Если позже появляется 401, ошибка модели или регрессия интерфейса, это уже другой класс инцидента, а не доказательство повторного отказа туннеля.

## Основание
Основание: ограниченные по области записи Brain о техобслуживании, уроках и каноне, а также история git этой ветки документации. Сырые журналы, приватные пути, домены/IP, email, секреты и конфигурации намеренно не публикуются.
