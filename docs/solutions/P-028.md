# P-028. Вложенная env-ссылка могла ломать авторизацию Notion MCP

**Статус:** гипотеза не подтверждена; найденные записи подтверждают hardening SecretRef/env и другие проблемы Notion, но не адресное исправление nested-env.

[English version](en/P-028.md)

## Симптом
Исходный индекс связывал Notion MCP auth failure с вложенной env reference. В доступных Brain-записях есть похожие элементы — SecretRef, перенос bearer token из argv, Authorization header из env, 403 и schema 400 — но нет прямого доказательства, что причиной была именно `nested env reference`.

## Условия
На 2026-05-24 Talos/OpenClaw уже использовал SecretRef/env для авторизации Notion и Supabase. Healthcheck показывал, что SecretRef env присутствовал, но прямой MCP initialize/list-tools для Notion возвращал HTTP 403. В тот же период отдельная schema-проблема Notion mutation tools решалась read-only ограничением.

## Что подтверждено
Hardening-проход перенёс Notion MCP bearer token из process argv в закрытый environment file для standalone service и заменил literal bearer header в OpenClaw config на env placeholder. После перезапуска Talos gateway вернулся в ready. Это подтверждённое улучшение обращения с секретами.

## Что не подтверждено
Не найдена запись, где показано: исходная вложенная env-ссылка раскрывалась неправильно, после изменения раскрытие стало корректным, и Notion MCP auth smoke прошёл именно из-за этого. Более того, отдельный healthcheck после появления SecretRef/env всё ещё фиксировал 403 для прямой MCP list-tools.

## Правильная классификация
Публичный кейс должен оставаться `unconfirmed`. Его нельзя выдавать за исправленную причину авторизации Notion. Доказанными остаются только: обращение с секретами улучшено; Notion schema issue обходился read-only allowlist; Notion/Supabase 403 позже были изолированы/disabled until smoke.

## Что нужно для закрытия
Нужен минимальный redacted reproduction: config fragment без секретов с вложенной env reference, фактический resolved header class без значения, 403 до изменения, новая форма env reference, затем успешный Notion MCP initialize/list-tools и хотя бы один read-only page/self call. Без этого nested-env остаётся гипотезой.
