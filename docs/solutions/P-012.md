# P-012. Cloudflare Access блокировал HTTP-01 продление сертификатов

**English:** [P-012](en/P-012.md)

**Статус:** подтверждённый результат. Сертификаты были продлены после узкого правила обхода; обычные маршруты остались за Access.

## Когда и при каких условиях
Случай зафиксирован 2026-08-04 на двух публичных именах хостов, где веб-интерфейсы были защищены Cloudflare Access, а Let’s Encrypt использовал HTTP-01 challenge. Схема DNS/proxy работала для пользователей, но ACME-валидатору требовался неаутентифицированный доступ к специальному пути.

## Симптомы
Продление сертификатов не проходило. Снаружи это могло выглядеть как проблема certbot, обратного прокси или DNS. На самом деле обычный пользовательский доступ был намеренно закрыт Access, и под эту же политику попадал путь `/.well-known/acme-challenge/*`.

## Причина
Подтверждённая причина: Cloudflare Access требовал авторизацию там, где ACME HTTP-01 должен получать простой HTTP/HTTPS-ответ без интерактивного входа. Let’s Encrypt не может пройти Access-политику как пользователь.

## Роли агента и пользователя
Пользователь хотел восстановить продление, не раскрывая админские интерфейсы. Агент должен был открыть только путь ACME challenge и только для нужных имён хостов, а не отключать Access целиком.

## Что не помогало или было опасно
- Временно отключать Access для всего сайта: это расширяет публичную поверхность больше, чем нужно.
- Перевыпускать сертификаты без изменения политики доступа: валидатор снова упрётся в авторизацию.
- Делать вывод «DNS сломан» только по ошибке HTTP-01: здесь DNS был недостаточным объяснением.

## Что сработало
1. Проверили, что путь challenge попадает под Access.
2. Добавили минимальный обход только для `/.well-known/acme-challenge/*` на нужных именах хостов.
3. Не меняли защиту обычных маршрутов.
4. Повторили продление.
5. Проверили срок действия новых сертификатов и доступность защищённых страниц через Access.

Безопасные обобщённые проверки:

```bash
curl -i https://example.com/.well-known/acme-challenge/test-token
certbot renew --dry-run
openssl s_client -connect example.com:443 -servername example.com </dev/null 2>/dev/null | openssl x509 -noout -dates
```

## Проверка результата
Оба сертификата были успешно продлены, новая дата истечения была зафиксирована, а обычные маршруты не стали публичными. Это подтверждает точечное решение именно для HTTP-01 за Access.

## Ограничения
Если политика безопасности не допускает даже узкого обхода для HTTP-01, используйте DNS-01. В Cloudflare важно проверять порядок и область правил: более широкая политика может перекрыть точечное исключение.

## Основание и уверенность
Основание: эксплуатационная запись о полной ремедиации VPS от 2026-08-04. Уверенность: высокая для причины и результата; средняя для переносимости на другие WAF/Access-конфигурации.
