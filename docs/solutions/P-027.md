# P-027. Некоторые инструменты Notion и Supabase MCP давали HTTP 403

**Статус:** открыто; подтверждённый нерешённый/жёлтый статус: 403 наблюдался, но адресное устранение в доступных записях не доказано.

[English version](en/P-027.md)

## Симптом
Аудит Talos/OpenClaw в режиме read-only зафиксировал, что настроенные MCP-серверы Notion и Supabase имели привязки SecretRef/env, но прямой MCP initialize/list-tools возвращал HTTP 403. При этом Notion service health был OK, Supabase URL был настроен как read-only, а Google Workspace и iMac MCP в том же проходе работали.

## Условия
Случай относится к Taloscopy healthcheck от 2026-05-24. Это был аудит в режиме read-only без исправлений, обновлений, перезапусков или ротации токенов. Поэтому сама запись честно классифицирует Notion/Supabase как partial, а не fixed.

## Что отличает этот случай от P-026
P-026 — schema validation/HTTP 400 у mutation tools Notion и подтверждённый обход через read-only. P-027 — HTTP 403 на уровне authorization/permission при MCP initialize/list-tools для Notion/Supabase. Эти проблемы нельзя объединять: успешное устранение schema 400 не доказывает исправление 403.

## Дальнейшие изменения
Позже Brain-регистры фиксируют более строгую позицию: MCP entries Talos/OpenClaw для Notion, Supabase и Cloudflare отключены до замены валидных токенов и live smoke. Standalone Notion service для Hermes остаётся отдельной возможностью. Это изоляция, а не доказательство, что исходный 403 был устранён.

## Проверка результата
Подтверждено: Google Workspace MCP и iMac MCP работали; прямой MCP smoke Notion/Supabase возвращал 403 на дату аудита; позднее активная Talos-конфигурация не должна молча заново включать эти entries без валидного token smoke. Не найден прямой receipt: `до 403`, `после 200`, tool list и scoped permission proof.

## Что нужно для закрытия
Нужен redacted auth audit: какой MCP endpoint, какой transport, какие scopes/headers без значений, какой exact request получил 403, затем повторный initialize/list-tools и минимальная read-only operation после исправления. Для Supabase отдельно нужен metadata/table-read smoke, потому что ранее SQL/table-доступ мог timeout-иться из-за состояния проекта.

## Публичная формулировка
Пишите: `403 был обнаружен и затем изолирован/не re-enabled без smoke`, а не `починено`. Это безопаснее и точнее для будущих операторов.
