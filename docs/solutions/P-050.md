# P-050. ARM64 Hermes Desktop не запускался на Intel iMac

**English:** [P-050](en/P-050.md)

## Статус
**Подтверждено на 2026-07-02; canon обновлён позже.** Официальные macOS DMG/app на проверенную дату были ARM64-only для Intel iMac, а собранный из исходников x86_64 Hermes Desktop работал как локальный lab/interface. Это не заменяло VPS production.

## Условия
- Дата первичного исправления: 2026-07-02.
- Устройство: Intel iMac (`x86_64`).
- Контур: Hermes Desktop macOS app, отдельный от VPS Hermes/Talos production.
- Участники: official DMG/app поставляет бинарник; local source build создаёт Intel-compatible app; launcher/profile запускают backend.

## Симптомы
Два скачанных official DMG и установленное приложение содержали ARM64 executable. Повторное скачивание не меняло результат, потому что файлы были идентичны по hash.

## Причина / гипотеза
На тот момент official Hermes macOS Desktop installer был ориентирован на Apple Silicon и поставлялся как ARM64-only. Intel iMac не мог использовать его как рабочий Desktop path. Требовалась source build под x86_64 или ожидание официального universal/x86_64 release.

## Неудачная последовательность
1. Повторно скачать official DMG.
2. Установить app в `/Applications`.
3. Проверить architecture executable.
4. Снова получить ARM64-only binary на Intel host.

## Успешная последовательность
1. Проверить architecture host и executable локальными системными инструментами.
2. Сравнить DMG hashes, чтобы исключить случайную порчу скачивания.
3. Собрать Electron/Desktop из исходников под x86_64.
4. Локально подписать app, привязать отдельный profile/runtime и launcher.
5. Не ставить второй production gateway на iMac.
6. Добавить update helper, который собирает из source, проверяет x86_64, выполняет smoke и rollback, а не использует official DMG.

## Проверка результата
- Два DMG совпали по SHA-256 и содержали ARM64 binary; installed official app тоже был ARM64.
- Source-built app определился как `x86_64`.
- Launcher сообщил Hermes Agent version и upstream revision.
- Backend из постоянного local profile дошёл до состояний dashboard-ready/startup-ready.
- Позднейший canon закрепил правило: Intel Desktop обновлять только controlled helper, не через official DMG, in-app update или blind update.

## Ограничения
- Local Intel app — lab/interface и fallback/update substrate, а не production VPS agent.
- Official DMG не стал Intel-compatible от локальной сборки.
- Актуальный статус нужно проверять перед будущими обновлениями: официальная поддержка может измениться, а local baseline уже обновлялся позже.

## Связанные случаи
- [P-048](P-048.md) — оба случая подчёркивают важность явного runtime/interpreter/architecture вместо ambient default.

## Уверенность доказательств
**Высокая.** Есть hash/architecture checks, successful source build, launcher/version receipt, backend-ready smoke и canon/update-policy receipts.
