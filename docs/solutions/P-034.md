# P-034. Публичный MCP gateway показывал слишком широкую административную поверхность

[English](en/P-034.md) · [Индекс](../problem-index.md)

**Статус:** частично подтверждено для состояния 2026-05-24; позднее политика менялась, поэтому текущую безопасность нужно проверять заново.

## Условия и симптомы

Во время аудита публичный MCP endpoint оказался функционально важным для доверенных клиентов, но набор зарегистрированных административных инструментов выглядел шире ожидаемого. Риск был не в самом факте регистрации инструмента, а в возможности выполнить опасный вызов через публичный контур.

## Причина и проверяемая гипотеза

Проверка разделила два уровня: обнаружение инструментов (tool discovery) и выполнение инструментов (tool execution). Инструмент может быть виден в списке ради совместимости, но заблокирован policy на этапе вызова. Поэтому проверяемая гипотеза звучала не как «виден ли инструмент», а как «исполняется ли административный вызов с реальным bearer и что получает неавторизованный клиент».

Общий безопасный smoke:

```sh
# 1. Без авторизации endpoint должен отказать.
# 2. С авторизацией опасный административный вызов должен вернуть policy error,
#    если такие инструменты выключены для публичной поверхности.
```

## Что помогло и что конфликтовало

Один актор ранее заблокировал admin tools как самостоятельное security-решение; отдельная запись зафиксировала, что без решения владельца так делать нельзя, потому что trusted workflows нуждались в shell/read доступе через OAuth. Позднее hardening-pass перенёс секрет из исходника в закрытое окружение и сделал legacy VPS admin tools disabled-by-default, оставив регистрацию для совместимости.

Иными словами, проблема была не в том, что «tools всегда нужно удалить», а в том, что нужно явно определить границу доступа (access boundary) и проверить фактический вызов.

## Проверка и ограничения

На дату hardening-pass запрос без авторизации возвращал отказ, OAuth metadata отдавалась, а тестовый административный вызов с валидной авторизацией возвращал policy error вместо исполнения. Ограничение: отдельная запись того же дня принимала обратное решение — разрешить административные функции доверенным клиентам через OAuth. Поэтому эту статью нельзя использовать как утверждение о текущей политике без свежей проверки действующих разрешений.

## Основание

Основание: закрытые записи об авторизации административных инструментов и ужесточении доступа от 2026-05-24. URL, секреты, значения токенов и сырые ответы не публикуются.
