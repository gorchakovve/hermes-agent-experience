# P-036. Документация о внешнем доступе расходилась с живой конфигурацией

[English](en/P-036.md) · [Индекс](../problem-index.md)

**Статус:** подтверждено для майской проверки: прямой запасной маршрут был закрыт, штатные маршруты оставались за внешней авторизацией.

## Условия и симптомы

Документация описывала панели агентов как защищённые внешним access-периметром. Аудит 24 мая 2026 года проверил не только named routes, но и прямой обходной путь к серверу. Настройки SSH также оказались шире желаемых. Риск: документ обещает защиту, но живой сервер может отдавать панель через route, который не проходит через access layer.

## Причина и проверяемая гипотеза

Причина — drift между каноном и реальной сетевой/служебной конфигурацией. Проверяемая гипотеза: named hostnames могут быть защищены, пока direct default host или запасной route остаётся открытым.

Общий безопасный порядок:

```sh
# Проверить штатный hostname: должен требовать внешнюю авторизацию.
# Проверить прямой/default route: не должен отдавать dashboard.
# Проверить SSH policy и firewall отдельно от reverse proxy.
```

## Что помогло

После backup ограничили способы SSH-входа и закрыли запасной веб-маршрут в конфигурации сервера, не ломая штатные named sites. Важная часть проверки — отрицательный кейс: «панель не открывается напрямую», а не только «сервис active».

## Проверка и ограничения

Запись сообщает: вход по ключу после изменения работал; прямой запрос больше не отдавал панель; штатные доменные маршруты требовали авторизацию; сервисы остались active. Ограничение: проверка с одного клиентского маршрута не равна внешнему pentest и не гарантирует будущие изменения конфигурации.

## Основание

Внутренние записи: майский storage/updater audit fixes и hardening records от 2026-05-24. Приватные адреса, домены, SSH-пути и сырые журналы не публикуются.
