# P-013. Watchdog выдавал критические предупреждения из-за устаревшего baseline

**English:** [P-013](en/P-013.md)

**Статус:** подтверждённый результат для ложноположительных сигналов, найденных 2026-06-15. Это не доказательство, что монитор обнаружит любой будущий отказ.

## Когда и при каких условиях
Инцидент произошёл после изменения схемы межагентных watcher-служб и появления новых штатных systemd-файлов для Brain watchdog. Старый монитор продолжал сравнивать систему с прежним baseline.

## Симптомы
Пользователь получал тревоги, выглядевшие как критические: якобы отсутствовали watcher-службы, а новые контрольные файлы считались подозрительными. При проверке выяснилось, что рабочий маршрут handoff уже был другим, а новые файлы относились к разрешённой служебной автоматизации.

## Причина
Подтверждённая причина: дрейф baseline. Монитор требовал retired units и не знал о легитимных файлах Brain watchdog. Дополнительный шум давали краткоживущие high UDP listeners, которые успевали попасть в один проход проверки.

## Роли агента и пользователя
Пользователь видел тревогу и нуждался в ответе: это реальный взлом/падение или шум? Агент должен был отличить retired units от текущих required units, не выключая контроль авторизации и не «леча» систему запуском старых сервисов.

## Что не помогало или было рискованно
- Запускать retired watcher-службы только ради зелёного watchdog: это возвращало бы старую архитектуру.
- Отключать watchdog целиком: шум исчез бы вместе с полезными сигналами.
- Добавлять все новые файлы в allowlist без проверки происхождения: это ухудшило бы контроль доступа.

## Что сработало
1. Сравнили старый и текущий маршрут watcher/handoff.
2. Удалили retired units из списка обязательных проверок.
3. Добавили легитимные файлы Brain watchdog в baseline.
4. Для кратких UDP listeners потребовали устойчивости между проходами, чтобы не будить пользователя из-за одноразового шума.
5. Оставили проверки gateway, текущих watcher-служб и access-сигналов.

Безопасные проверки:

```bash
systemctl --user list-units '*watch*' --no-pager
python -m py_compile path/to/watchdog.py
python path/to/watchdog.py --status
```

## Проверка результата
Компиляция watchdog-скриптов прошла. Прямые запуски очистили stale service alerts; состояние infrastructure issues и active access alerts стало пустым. Актуальные gateway и watcher units были active.

## Ограничения
Это исправление ложноположительных сигналов. Отдельный false-negative тест с искусственным отказом в записи не зафиксирован.

## Основание и уверенность
Основание: maintenance receipt «Watchdog Noise Baseline Alignment» от 2026-06-15 и связанный Hermes review. Уверенность: высокая для устранённого шума; средняя для полноты будущего мониторинга.
