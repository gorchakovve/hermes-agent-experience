# P-022. Прямой доступ VPS к Gemini ограничивался регионом

**Статус:** подтверждено на дату проверки; применён рабочий обход через раздельные proxy-входы, но региональная доступность upstream может меняться.

[English version](en/P-022.md)

## Симптом
Прямой запрос с VPS к Google Generative Language API возвращал отказ по местоположению: сервис считал регион недопустимым для использования API. Из-за этого резерв Gemini нельзя было проверять или включать как обычный прямой HTTPS-доступ.

## Условия
На VPS одновременно работали Hermes и Talos/OpenClaw. Hermes был настроен на локальный SOCKS-вход Gemini-прокси, а OpenClaw ожидал явный HTTP(S) proxy. Попытка подставить SOCKS URL в OpenClaw приводила к отдельной ошибке формата/транспорта и не решала региональный отказ.

## Причина
Причина была не в модели и не только в ключе. Прямой датацентровый egress VPS попадал под региональную блокировку Google AI. Дополнительная инженерная причина — несовместимость ожиданий клиентов: одна среда runtime принимала SOCKS5, другая требовала HTTP proxy. Поэтому один локальный порт не мог безопасно обслуживать оба клиента без адаптации.

## Что было сделано
Для OpenClaw был выделен отдельный HTTP-вход того же защищённого xray-маршрута, при этом Hermes сохранил свой SOCKS-вход. Затем provider-конфигурацию Google для OpenClaw перевели на HTTP proxy и перезапустили только нужный gateway. Разделение входов стало постоянным инвариантом: Hermes не должен терять SOCKS-маршрут, а Talos/OpenClaw — HTTP-маршрут.

## Проверка результата
После изменения Google API через HTTP proxy вернул HTTP 200 и список моделей; ошибка о недопустимом `socks5` URL исчезла. Отдельный Telegram smoke Talos на Gemini прошёл. Более поздние Brain-регистры также фиксируют оба прокси-порта как защищённый инвариант, который нельзя удалять при обновлениях.

## Что не доказано
Проверка доказывала доступность конкретного маршрута на конкретную дату, а не постоянную пригодность выбранного upstream. Она также не означала, что любые Google UI-сервисы, NotebookLM или аккаунтные сценарии работают через тот же маршрут: для них нужны отдельные signed-in проверки, см. [P-025](P-025.md).

## Практический вывод
Если прямой запрос из датацентра получает regional refusal, не меняйте ключи вслепую. Сначала отделите прямой egress, proxy egress и формат proxy, который поддерживает конкретный клиент. Для OpenClaw/Hermes раздельные HTTP и SOCKS-входы были не избыточностью, а способом совместить два среды runtime.
