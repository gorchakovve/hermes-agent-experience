# P-017. Device-code relogin упёрся в rate limit, но runtime ещё отвечал

**English:** [P-017](en/P-017.md)

**Статус:** частично подтверждённый результат. 429 device-code flow не был «исправлен» в записи; вместо этого доказали, что текущий runtime ещё отвечает, и прекратили автоматические попытки relogin.

## Когда и при каких условиях
12 июня 2026 Hermes имел Codex OAuth state с `relogin_required=true`. Оператор попытался пройти device-code relogin, но OpenAI вернул HTTP 429. Ранее существовал watchdog, который пытался выполнять device-code refresh/login автоматически; этот паттерн уже был признан опасным.

## Симптомы
State говорил о необходимости relogin, а login flow отвечал 429. Это создавало ловушку: чем активнее агент пытается «починить» авторизацию, тем выше риск усилить rate limit и создать новые prompts/timeouts.

## Причина или проверяемая гипотеза
Подтверждено: 429 относился к device-code login/polling path. Одновременно минимальный runtime-запрос к Codex route вернул sentinel, значит флаг relogin не равнялся полной текущей недоступности модели. Причина самого 429 не была устранена отдельным изменением.

## Роли агента и пользователя
Пользователь не должен получать бесконечные инструкции по входу или новые prompts без явной необходимости. Агент должен был остановить автоматический relogin, проверить фактическую работоспособность и уведомлять о повторении проблемы, не пытаясь чинить её самостоятельно.

## Что не помогало или было рискованно
- Повторять device-code flow после 429.
- Запускать cron/watchdog, который сам выполняет login/add.
- Объявлять runtime сломанным без live smoke.
- Хранить или печатать токены для ручной диагностики.

## Что сработало
1. Остановились после 429, не усиливая поток авторизации.
2. Выполнили минимальный Codex smoke с ожидаемым текстом.
3. Перечитали не-секретный auth state.
4. Поставили alert-only watchdog: он сообщает о `relogin_required` и recovery, но не запускает OAuth repair.

## Проверка результата
Smoke вернул `CODEX_OK`; после этого `relogin_required` исчез или стал отсутствовать. Dry run watchdog сообщил OK, а путь уведомления и recovery был проверен. Это подтверждает рабочий runtime на момент проверки.

## Ограничения
Запись не доказывает, что device-code 429 больше не повторится. Также нет отдельного теста полного интерактивного relogin после cooldown. История закрывает только вредный автоматический relogin и подтверждает текущую работоспособность.

## Основание и уверенность
Основание: maintenance receipt Hermes Codex OAuth relogin incident и lesson от 2026-06-12. Уверенность: высокая для runtime smoke; низкая-средняя для устранения самого 429 device-code flow.
