# P-088. Исправление уязвимых YAML-зависимостей не означает, что обновлено установленное Desktop-приложение

[English](en/P-088.md) · [Индекс](../problem-index.md)

**Статус:** подтверждено для production-зависимостей проверенной сборки; полный набор dev-зависимостей не закрыт.

## Условия и симптомы

25 сентября 2026 года проверка исходников Hermes выявила production-зависимости `js-yaml` и `yaml`, которые требовали обновления. Одного изменения lockfile на VPS было недостаточно: оно не обновляло уже установленную сборку Hermes Desktop на Intel iMac. Настольное приложение нужно было отдельно собрать и установить. Работающий Python gateway сам по себе не доказывал, какие версии Node-пакетов включены в приложение.

## Причина и действия

По записи о ремонте, исполнитель обновил `js-yaml` с 4.3.1 до 4.3.2 и `yaml` с 2.8.1 до 2.8.3 в ограниченном наборе manifest/lock-файлов. Он проверил дерево установленных production-зависимостей, выполнил аудит, типизацию, тематические тесты и изолированную сборку. Затем на Intel iMac собрал приложение из той же ревизии исходников с тем же патчем, установил его и сопоставил контрольную сумму установленного пакета с собранным артефактом. Это запись работы другого исполнителя, а не утверждение о моём личном запуске этих команд.

Безопасный способ повторить проверку **в своём checkout** после обновления зафиксированных зависимостей:

```sh
npm ls js-yaml yaml --omit=dev
npm audit --omit=dev
```

Не обновляйте lockfile вслепую: отдельно проверяйте фактически установленное приложение и используйте штатный путь сборки/обновления, совместимый с архитектурой устройства.

## Проверка и границы

В записи от 25 сентября: `npm audit --omit=dev` показал ноль уязвимостей на VPS и в установленном профиле Desktop; три набора тематических тестов (9 тестов), типизация и сборка прошли. Проверка подписи и совпадения checksum установленного приложения с результатом проверенной сборки тоже прошла; smoke-test Desktop и связь с backend были успешными. **Это не утверждение, что все dev-зависимости безопасны:** полный аудит с ними всё ещё показывал шесть замечаний. При следующем upstream-обновлении нужно заново подтвердить, что фиксированные версии не откатились.

См. также [P-053](P-053.md) о правах npm cache при предыдущей сборке и [P-089](P-089.md) о гонке резервного копирования в том же окне обновления.

## Основание

Сводная техническая запись исполнителя от 25 сентября 2026 года с результатами аудита, тестов, сборки и сверки установленного артефакта; исходные служебные пути, конфигурации и журналы здесь не публикуются.
