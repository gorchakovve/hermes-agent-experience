# P-041. Межагентная передача теряла подтверждение или дублировалась

**English:** [P-041](en/P-041.md)

## Статус
**Подтверждено для исправленного контура на 2026-06-21.** Проверены оба направления Hermes↔Talos/OpenClaw, fallback без HTTP-bridge и отказ от повторного использования уже закрытого task ID. Исторические задачи, созданные до введения enforcement, не считаются автоматически закрытыми.

## Условия
- Дата инцидента и исправления: 2026-06-21.
- Контур: межагентный HTTP-bridge Hermes↔Talos/OpenClaw и файловый fallback через Brain inbox.
- Участники: отправитель создаёт задачу; bridge или файловый watcher доставляет её; принимающий runner исполняет; ledger фиксирует жизненный цикл.

## Симптомы
Файловая передача могла оставлять жизненный цикл незакрытым, дублировать task ID или запускать runner на невалидном файле из inbox. Наличие транспорта само по себе не доказывало, что получатель увидел задачу, подтвердил её и закрыл результатом или блокером.

## Причина / гипотеза
До исправления не было обязательного единого lifecycle-ledger и строгой валидации protocol-v1 до запуска runner. Из-за этого watcher мог среагировать на мусорный файл, а закрытие задачи зависело от разрозненных транспортных статусов.

## Неудачная последовательность
1. Агент отправлял задачу через bridge или fallback.
2. Watcher видел файл в inbox.
3. Без строгой проверки файл мог быть принят как задание.
4. Повторный или незакрытый task ID не получал достаточно сильного терминального состояния.

## Успешная последовательность
1. Ввести единый sender и task ID.
2. Записывать в ledger события `send → received → ack → accepted → resolved/blocked → closed`.
3. Перед запуском runner валидировать protocol-v1.
4. Невалидные файлы помещать в quarantine без исполнения.
5. Повтор закрытого ID отклонять как duplicate/closed, если оператор явно не форсирует исключение.
6. Отдельно проверить fallback при отключённом bridge и восстановление bridge.

## Проверка результата
- Smoke-проверки Hermes→Talos и Talos→Hermes дошли до `closed`.
- Невалидный task-файл был помещён в quarantine, runner не запускался.
- Повтор закрытого task ID был отклонён.
- При остановленном bridge fallback создал валидную задачу, watcher обработал её, ledger дошёл до `closed`, после чего bridge восстановили.
- Текущий отчёт open-loop не содержал незакрытых реальных циклов; тестовый quarantine-артефакт оставлен как доказательство поведения.

## Ограничения
- Исправление не доказывает корректность всех старых handoff'ов, сделанных до enforcement.
- Возможные transport warnings после полезного stdout классифицированы отдельно; это не та же проблема, что незакрытый lifecycle.
- Сырые пути, логи, адреса и конфигурация не публикуются.
