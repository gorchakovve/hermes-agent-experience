# P-043. OpenClaw молчал в Telegram-группе из-за `NO_REPLY`

**English:** [P-043](en/P-043.md)

## Статус
**Частично подтверждено на 2026-06-21.** Конфигурационное исправление применено и прочитано обратно, gateway поднялся, Telegram переподключился. Прямая пользовательская проверка нового сообщения после исправления в исходном receipt не зафиксирована.

## Условия
- Дата: 2026-06-21.
- Контур: Talos/OpenClaw в Telegram forum/group topic.
- Участники: модель могла вернуть sentinel `NO_REPLY`; promise guard просил revise; верхний pipeline решал, делать ли retry или видимую доставку.

## Симптомы
На сообщения, явно требовавшие ответа, модель дважды вернула только `NO_REPLY`. Guard логировал необходимость revise/force reply, но итоговая доставка подавлялась, и пользователь видел молчание.

## Причина / гипотеза
Групповой Telegram route наследовал default silent-reply policy: group = allow. При такой policy system prompt разрешал `NO_REPLY`, а нижестоящий pipeline считал пустой или silent-ответ допустимым и не запускал retry, несмотря на revise request от guard. Это не тот же сбой, что unsupported Telegram message.

## Неудачная последовательность
1. Сообщение в forum/group topic достигает агента.
2. Модель выбирает sentinel `NO_REPLY`.
3. Guard корректно просит revise.
4. Delivery pipeline трактует silent reply как разрешённый и завершает ход без видимого ответа.

## Успешная последовательность
1. Проверить schema/config для версии OpenClaw.
2. Если бот должен отвечать на разрешённые групповые запросы, установить Telegram group silent reply policy в `disallow` через поддерживаемый config-механизм.
3. Выполнить config validate.
4. Прочитать значение обратно.
5. Перезапустить только нужный gateway и проверить реальное сообщение в том же topic.

## Проверка результата
Внутренний receipt подтверждает: dry-run/validate прошли, значение group silent policy прочитано как `disallow`, gateway стартовал, Telegram provider переподключился. Видимый пользователю live reply после этого в receipt не подтверждён.

## Ограничения
- Не применяйте это глобально к группам, где бот намеренно должен молчать.
- Это per-surface Telegram-настройка OpenClaw/Talos, а не настройка Hermes или других каналов.
- Для полного закрытия нужно реальное сообщение в затронутом topic и видимый ответ.

- [P-044](P-044.md), [P-045](P-045.md), [P-047](P-047.md) — другие Telegram-сбои были связаны с rich payload rendering, а не с молчанием.
