# P-046. В Telegram-топике сохранялся устаревший message-tool контекст

**English:** [P-046](en/P-046.md)

## Статус
**Частично подтверждено на 2026-06-14.** Узкий reset конкретной topic-session был выполнен безопасно, но следующая smoke-проверка пользовательским сообщением после reset не зафиксирована, поэтому исправление нельзя считать полностью проверенным.

## Условия
- Дата: 2026-06-14.
- Контур: Talos/OpenClaw Telegram topic после перехода доставки с `message_tool` на automatic replies.
- Участники: Telegram delivery успешно отправлял финальный ответ; session state дополнительно подтягивал старый tool context.

## Симптомы
Финальный ответ доходил, но одновременно появлялась видимая плашка `Message failed`. Это выглядело как ошибка Telegram-доставки, хотя основной outbound send уже был успешен.

## Причина / гипотеза
В session state конкретного Telegram topic сохранился старый контекст `message` tool. После перехода на automatic reply этот stale context всё ещё пытался вызвать отсутствующий tool path и создавал отдельную ошибку рядом с успешной отправкой.

## Неудачная последовательность
1. Доставка переключена на automatic replies.
2. Старый topic-session остаётся в состоянии до миграции.
3. Новый ответ отправляется успешно.
4. Старый tool context дополнительно пытается вызвать `message` tool и даёт видимую ошибку.

## Успешная последовательность
1. Сначала проверить, что config valid, gateway active и реальная отправка успешна.
2. Убедиться, что ошибка относится к session/tool context, а не к Telegram auth/login.
3. Сделать backup.
4. Переместить или архивировать только файлы затронутой topic-session, ничего глобально не удаляя.
5. На следующем пользовательском сообщении проверить отсутствие повторного tool error.

## Проверка результата
До reset были подтверждены config valid, active gateway и успешный outbound send. Файлы конкретной topic-session были перемещены в архивный suffix, не удалены. Receipt содержит ожидаемое поведение следующего сообщения, но не содержит smoke-проверки после reset.

## Ограничения
- Нужна новая smoke-проверка пользовательским сообщением именно в этом topic.
- Нельзя заявлять проверенное исправление без подтверждения, что `Message failed` не повторяется после reset.
- Не переносите этот метод на другие topic/session без отдельной диагностики.

## Связанные случаи
- [P-044](P-044.md), [P-045](P-045.md), [P-047](P-047.md) — Telegram ошибки рендера; здесь отправка была успешной, а ошибка шла из устаревшего session context.

## Уверенность доказательств
**Средняя для диагноза, низко-средняя для полного исправления.** Логи разделили successful send и stale tool lookup, но post-reset smoke отсутствует.
