# P-039. Результат OpenClaw писался не туда и неверно разбирался из JSON

[English](en/P-039.md) · [Индекс](../problem-index.md)

**Статус:** подтверждено ручным и автоматическим smoke на дату 2026-04-22.

## Условия и симптомы

Автоматический цикл Hermes → Talos/OpenClaw → result-file не возвращал ожидаемый ответ. Пользовательский симптом был «handoff не завершился», хотя отдельные части стека могли быть живы.

## Причины и проверяемые гипотезы

Разбор выявил несколько причин одновременно:

1. runner запускал OpenClaw в устаревшем локальном режиме;
2. result directory указывал не туда;
3. JSON parser читал `.text`, хотя фактический ответ находился глубже в структуре результата;
4. systemd environment мог выбирать старый CLI через PATH.

Из-за одновременности исправлений нельзя честно приписать успех одному патчу. Проверяемый критерий был end-to-end: ручной runner smoke и автоматический watcher smoke должны оба вернуть ожидаемый текст.

## Что помогло

Помогли четыре изменения: убрать старый local-mode launch, закрепить корректный бинарник, исправить каталог результата и использовать правильный JSON path. Для похожих runner-интеграций полезно проверять не только stdout CLI, но и фактический файл, который читает следующий этап.

Пример общей проверки JSON path:

```sh
jq -r '.result.payloads[0].text' result.json
```

## Проверка и ограничения

В записи от 2026-04-22 зафиксированы два smoke: ручной result `RUNNER_SMOKE_OK` и автоматический watcher result `WATCHER_AUTO_OK`. Ограничение: это доказывает, что цикл заработал после набора изменений; оно не доказывает индивидуальный вклад каждой правки.

## Основание

Внутренняя запись «Hermes ↔ Talos auto-cycle fixed» от 2026-04-22. Абсолютные приватные каталоги result-файлов и сырые task-файлы не публикуются.
