# P-003. OpenClaw update landed in an inactive package tree

**Status:** confirmed by the 2026-07-02 update note.

**Evidence:** MAINTENANCE note from 2026-07-02; direct comparison of updater target, active package tree, CLI version, service health, and public guard. Raw logs, private paths, tokens, domains, and addresses are intentionally omitted.

**RU:** [`P-003.md`](../P-003.md)

## Symptoms
The updater reported that a new version was installed, but the active CLI and gateway stayed on the old version.

## Conditions and timing
VPS, 2026-07-02; two local OpenClaw npm/package-tree installations.

## Hypothesis / root cause
The updater wrote into an inactive package tree, while systemd launched a different active tree.

## Actions that worked
Compared the gateway unit, command -v openclaw, CLI version, and the actual Node module tree. Updated the updater/repair helpers so they target the active package tree; then re-ran repair against the active copy and restarted the gateway.

## Verification
The active CLI became 2026.6.11, the gateway was active, local /health returned live, and the public endpoint guard passed without failures/warnings.

## Limitations
Do not copy runtime paths across hosts: discover the active service/package path first. A successful install in logs does not prove the runtime was updated.
