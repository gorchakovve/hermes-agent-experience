# P-076. The Drive mirror created duplicates and stale state

**Status:** confirmed. Sync was repaired around parent+filename reconciliation, dry-run/dedupe/state checks and safe duplicate archiving.

**Русская версия:** [P-076](../P-076.md)

## Timeframe and conditions
2026-06-06 and later checks. Google Drive was used as a Brain mirror for humans and external AI tools, not as the source of truth.

## Symptoms
Repeated copies of the same Brain files appeared in Drive. The local sync state pointed at missing or moved items, so the next sync could create new files instead of updating existing ones.

## Confirmed cause vs hypothesis
Confirmed: create ran without enough checking of the “target folder + filename” pair, while saved sync state could be stale. Identical names in the same folder became duplicate groups.

Hypothesis not to accept blindly: that every similar name is a duplicate. In Drive, similar names can represent different documents.

## Actor attribution and actions
The operator added/used dedupe report, archive duplicates, reconcile state and dry-run modes. Confirmed duplicates were archived, not permanently deleted. State was reconciled against actually existing Drive file IDs, then dry-run was repeated.

## Practical verification
Safe order:

```sh
sync-brain-to-drive --dry-run
sync-brain-to-drive --dedupe-report
sync-brain-to-drive --archive-duplicates
sync-brain-to-drive --reconcile-state
sync-brain-to-drive --dry-run
```

These commands are intentionally generic: use the real wrapper/script in your environment, but preserve the order “report → archive → reconcile → dry run”.

## Proof of result
In the confirmed record, duplicate groups were gone after the fix; the following dry-run created and archived nothing. The registry describes the sync as idempotent: it checks Drive parent+filename before create and supports dedupe/state reconciliation.

## Limits and open items
Drive remains a mirror. Brain/git remains the source of truth. Before archiving, inspect the content and purpose of similar documents, especially when names differ only by suffix, date or manual marker.

## Lesson
Mirror sync must be idempotent. If sync cannot find an existing file in the intended folder by name before create, it will eventually create duplicates.
