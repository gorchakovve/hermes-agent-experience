# P-034. The public MCP gateway exposed a wider administrative surface than intended

[Русский](../P-034.md) · [Index](../../problem-index.en.md)

**Status:** partially verified for the 24 May 2026 state; policy changed later, so current safety requires a fresh check.

## Conditions and symptoms

During an audit, the public MCP endpoint was operationally important for trusted clients, but the registered administrative tool surface looked broader than expected. The risk was not merely tool registration; it was whether a dangerous call could execute through the public path.

## Cause and testable hypothesis

The review separated two layers: tool discovery and tool execution. A tool can remain listed for compatibility while execution is blocked by policy. The testable question was therefore not “is the tool visible?” but “does an administrative call execute with a real bearer, and what does an unauthenticated client receive?”

Generic smoke:

```sh
# 1. Without auth, the endpoint should reject the request.
# 2. With auth, a dangerous admin call should return a policy error
#    if such tools are disabled for the public surface.
```

## What helped and what conflicted

One actor had previously blocked admin tools as an independent security decision; a separate record says that removing another agent's capability needs owner approval because trusted workflows needed shell/read access through OAuth. A later hardening pass moved a client secret out of source and made legacy VPS admin tools disabled-by-default, while keeping registration for compatibility.

The lesson is not “always delete tools”; it is “define the access boundary explicitly and test execution, not just discovery.”

## Validation and limits

At the hardening point, unauthenticated requests were rejected, OAuth metadata was available, and an authenticated admin-tool test returned a policy error instead of executing. Limit: another same-day record accepted administrative capabilities for trusted clients through OAuth. Do not infer the current policy without rechecking the effective permissions.

## Evidence

Evidence: private records of administrative-tool authorization and access hardening dated 24 May 2026. URLs, secrets, bearer values and raw responses are omitted.
