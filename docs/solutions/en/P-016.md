# P-016. `relogin_required` did not always mean the model was currently unavailable

**Русский:** [P-016](../P-016.md)

**Status:** confirmed result for the 2026-06-12 incident. A live smoke worked and cleared the stale auth error; future refresh was not proven.

## Timing and conditions
Hermes was using a Codex OAuth route. Auth state already contained historical `refresh_token_reused` / `relogin_required=true`, and an interactive device-code relogin attempt during repair hit HTTP 429.

## Symptoms
State made it look as if relogin was required. An operator could conclude the model was unavailable and start repeated device-code login attempts. In reality, a minimal live model request could still succeed.

## Cause or testable hypothesis
Confirmed: historical auth error and current runtime ability had diverged. `relogin_required` reflected a recorded refresh-token reuse issue, but it was not sufficient proof that every current request was already impossible. After a successful smoke, the stale error disappeared from state.

## Agent/user distinction
The user needed a working agent and risk notification. The agent should not run endless OAuth login attempts, especially after 429. The correct role was to run a safe minimal runtime smoke and install alert-only monitoring, not an automatic repair loop.

## What did not help or was risky
- Repeating device-code login after 429.
- Printing or copying OAuth tokens for diagnostics.
- Treating the auth-state flag as the only source of truth.
- Automatically “fixing” OAuth from cron.

## What worked
1. Read only non-secret auth fields: provider, error code, relogin flag, timestamp.
2. Run a minimal live model smoke.
3. If the smoke succeeds, re-read state and verify the stale error disappeared or no longer blocks operation.
4. Add an alert-only watchdog: detect `relogin_required`, notify, but do not run login/refresh.

Safe smoke pattern:

```bash
hermes chat -Q --provider openai-codex -m MODEL -q 'Reply exactly: OK'
# then inspect state without printing tokens
```

## Verification
The minimal request returned the expected sentinel. Afterward, `last_auth_error` was absent and `relogin_required` was not set. The watchdog dry run reported OK, and the alert/recovery send path was verified as sendable.

## Limits
One successful request does not prove future refresh, especially with rotating tokens. The watchdog only reports a new flag; it does not repair OAuth.

## Evidence and confidence
Evidence: 2026-06-12 Hermes Codex OAuth relogin maintenance receipt and lesson. Confidence: high for current smoke/result; medium for long-term credential stability.
