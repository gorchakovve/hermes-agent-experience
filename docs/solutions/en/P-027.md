# P-027. Some Notion and Supabase MCP tools returned HTTP 403

**Status:** open; confirmed unresolved/yellow status: 403 was observed, but a targeted fix is not proven in the available records.

[Русская версия](../P-027.md)

## Symptom
A Talos/OpenClaw read-only audit found that configured Notion and Supabase MCP servers had SecretRef/env wiring, but direct MCP initialize/list-tools returned HTTP 403. In the same pass, Google Workspace and iMac MCP worked, and Notion service health itself was OK.

## Conditions
The case belongs to the 2026-05-24 Taloscopy healthcheck. It was a read-only audit: no fixes, updates, restarts, or token rotations. The record therefore classifies Notion/Supabase as partial, not fixed.

## How this differs from P-026
P-026 is a schema validation/HTTP 400 issue in Notion mutation tools with a confirmed read-only workaround. P-027 is authorization/permission-level HTTP 403 during MCP initialize/list-tools for Notion/Supabase. These must not be merged: fixing schema 400 does not prove fixing 403.

## Later state
Later Brain registries take a stricter position: Talos/OpenClaw MCP entries for Notion, Supabase, and Cloudflare are disabled until valid tokens are replaced and live smokes pass. Standalone Notion service for Hermes remains a separate capability. That is containment, not proof that the original 403 was repaired.

## Verification
Confirmed: Google Workspace MCP and iMac MCP worked; Notion/Supabase direct MCP smoke returned 403 on the audit date; later active Talos config should not silently re-enable those entries without valid-token smoke. I did not find a direct receipt showing before-403, after-200, tool list, and scoped permission proof.

## Closure criteria
A closure record needs a redacted auth audit: MCP endpoint, transport, scopes/headers without values, the exact request that got 403, then a repeated initialize/list-tools and minimal read-only operation after the fix. Supabase also needs a metadata/table-read smoke because previous SQL/table access could time out due to project state.

## Public wording
Say: `403 was detected and later contained/not re-enabled without smoke`, not `fixed`. That is safer and more accurate for future operators.
