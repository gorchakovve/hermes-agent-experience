# P-017. Device-code relogin hit a rate limit while runtime still responded

**Русский:** [P-017](../P-017.md)

**Status:** partially confirmed result. The 429 device-code flow was not “fixed” in the record; instead, current runtime response was proven and automatic relogin attempts were stopped.

## Timing and conditions
On 2026-06-12 Hermes had Codex OAuth state with `relogin_required=true`. An operator attempted device-code relogin, but OpenAI returned HTTP 429. A previous watchdog had attempted device-code refresh/login automatically; that pattern was already considered unsafe.

## Symptoms
State said relogin was required, while the login flow returned 429. This created a trap: the harder the agent tried to “fix” auth, the more likely it was to worsen rate limiting and create more prompts/timeouts.

## Cause or testable hypothesis
Confirmed: the 429 applied to the device-code login/polling path. At the same time, a minimal runtime request through the Codex route returned a sentinel, so the relogin flag did not equal complete current model unavailability. The root cause of the 429 itself was not removed by a separate fix.

## Agent/user distinction
The user should not receive endless login instructions or new prompts unless truly required. The agent needed to stop automatic relogin, test actual runtime ability, and notify on recurrence without trying to repair OAuth by itself.

## What did not help or was risky
- Repeating the device-code flow after 429.
- Running a cron/watchdog that calls login/add by itself.
- Declaring runtime broken without a live smoke.
- Storing or printing tokens for manual diagnosis.

## What worked
1. Stopped after 429 instead of increasing auth traffic.
2. Ran a minimal Codex smoke expecting an exact text response.
3. Re-read non-secret auth state.
4. Installed an alert-only watchdog: it reports `relogin_required` and recovery, but does not run OAuth repair.

## Verification
The smoke returned `CODEX_OK`; afterward `relogin_required` disappeared/was absent. Watchdog dry run reported OK, and the alert/recovery path was checked. This verifies runtime availability at the time of the check.

## Limits
The record does not prove the device-code 429 will not recur. It also lacks a separate full interactive relogin test after cooldown. The story closes the unsafe automatic-relogin behavior and verifies current runtime, not the device-code service.

## Evidence and confidence
Evidence: 2026-06-12 Hermes Codex OAuth relogin maintenance receipt and lesson. Confidence: high for runtime smoke; low-medium for eliminating the device-code 429 path.
