# P-047. Telegram formatting required repairing both agents

**Русская версия:** [../P-047.md](../P-047.md)

## Status
**Verified by server-side smokes as of 2026-06-18.** Talos/OpenClaw and Hermes were moved to plain-compatible Telegram delivery, and both gateways were active. Full visual proof on every client is not claimed.

## Conditions
- Date: 2026-06-18.
- Surface: Talos/OpenClaw and Hermes, both sending to Telegram.
- Actors: two different agent runtimes have different Telegram adapters; one repair does not cover the other runtime.

## Symptoms
After the Talos-only plain-send repair, the user still saw Telegram unsupported/update blocks, now on replies from both agents.

## Cause / hypothesis
Talos text send was partly plain, but preview/final rich-edit capabilities and a rich edit path remained. Hermes had its own Telegram adapter and could use Bot API rich messages/drafts independently of OpenClaw.

## Failed sequence
1. Only Talos text send is repaired.
2. Talos edit/preview paths remain rich-capable.
3. Hermes is not touched by the Talos repair at all.
4. The user continues seeing unsupported blocks from both Talos and Hermes.

## Successful sequence
1. Back up both runtimes.
2. Force Talos/OpenClaw plain send/edit and disable live preview/final/progress/rich capabilities.
3. Disable Hermes's Telegram rich gate so it does not use Bot API rich delivery.
4. Add the shared repair to the post-update helper.
5. Run Node/Python syntax checks and config validation, then restart only the affected gateways.
6. Perform real send smokes from both agents.

## Verification
- Node syntax for OpenClaw and Python compile for Hermes passed.
- OpenClaw config validation passed.
- Both gateways became active after restart.
- Talos real-agent smoke arrived as a plain text operation.
- Hermes send smoke arrived with literal-markdown/plain-text intent.
- The post-update helper confirmed compatibility markers.

## Limitations
- This is a server-side send/log smoke, not screenshot proof on every client.
- Later package versions may rename bundle files or add new paths; the repair must run after updates.
- P-045 showed that tool progress/system paths can be separate even after this baseline.

## Related cases
- [P-044](P-044.md) — Talos-only first pass.
- [P-045](P-045.md) — progress/system path gaps after the baseline.

## Evidence confidence
**High for server-side delivery, medium for full client UX.** Evidence includes compile/syntax/config checks, service health, and two-agent send smokes; there is no blanket visual proof across all Telegram clients.
