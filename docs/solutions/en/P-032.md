# P-032. Cloudflare and Netlify access were not equivalent

[Русский](../P-032.md) · [Index](../../problem-index.en.md)

**Status:** partially verified: Netlify and the repaired Cloudflare account-token check passed, but this is not a full deploy smoke for every service.

## Conditions and symptoms

On 24 May 2026, the agent stack needed to publish small web artifacts and manage the public perimeter. Netlify API reads worked, while Cloudflare verification through the user-token endpoint returned 401. Cloudflare Access for public routes still worked, so this was not evidence that all Cloudflare functionality had failed.

## Cause and testable hypothesis

The token type and verification endpoint did not match. The token was account-level but was checked as a user token. These surfaces must be separated:

```sh
# user token: /user/tokens/verify
# account token: /accounts/<account_id>/tokens/verify
```

Cloudflare Access, DNS/deploy APIs and Netlify APIs are distinct. A pass in one does not prove the others, and a 401 from the wrong verify endpoint does not prove the Access perimeter is down.

## What helped and what was left untouched

After owner confirmation, token values were replaced in private environment files, the watchdog was changed to verify account tokens through the account endpoint, and two gateways were restarted. DNS, Access apps, Workers, Pages and zone records were not changed.

What did not help was trying to “fix deployment” by weakening Cloudflare Access. The record explicitly separates Access perimeter health from API-token health.

## Validation and limits

The record reports an active account-token verification, a watchdog run that reported recovery, and both gateways active. Netlify had already been verified by account/project reads. Limit: there is no separate post-repair Cloudflare MCP read/deploy smoke in the record, so this should not be reported as “all Cloudflare/Netlify operations fully verified.”

## Evidence

Internal records: “Cloudflare and Netlify Deploy Capability Priority” dated 24 May 2026 and its Cloudflare token repair section. Tokens, account IDs, domains and raw logs are omitted.
