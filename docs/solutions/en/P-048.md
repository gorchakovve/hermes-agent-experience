# P-048. Seeker digest ran under system Python without a dependency

**Русская версия:** [../P-048.md](../P-048.md)

## Status
**Partially verified as of 2026-09-26.** The cron command was changed to the project venv Python and ran successfully when executed directly. The next scheduled cron run and downstream delivery were not yet confirmed in the receipt.

## Conditions
- Date: 2026-09-26.
- Surface: Seeker Invest daily digest as a Hermes cron job, Python project with `.venv` and PyYAML dependency.
- Actors: cron starts the command; the Python interpreter imports dependencies; the digest script produces output.

## Symptoms
Cron used a relative script/ambient interpreter and failed importing `yaml`, even though the project dependency was declared and installed in the virtual environment.

## Cause / hypothesis
The scheduler was using the wrong interpreter. In the project `.venv`, `yaml` imported successfully; ambient/system Python lacked PyYAML.

## Failed sequence
1. Cron starts the script without an explicit project venv Python.
2. The shell/environment chooses an ambient interpreter.
3. Importing `yaml` fails.
4. The digest is not produced despite a correct project dependency.

## Successful sequence
1. Test the dependency import in ambient Python and in the project venv.
2. Do not change schedule, permissions, sources, or delivery policy.
3. In the existing cron job, change only the command to the absolute `.venv/bin/python` path plus the same script and arguments.
4. Run the exact command directly.
5. Read the cron job back and confirm schedule and restrictions are unchanged.
6. After the next scheduled run, verify end-to-end delivery.

## Verification
A direct run of the exact project-venv command exited 0, produced non-empty output, and had empty stderr. Cron job readback showed enabled status, the original schedule, the venv path in the prompt/command, and preserved read-only/delivery constraints.

## Limitations
- The first scheduled run after the change was not captured.
- Downstream digest delivery is not proven by this smoke.
- A separate OAuth/Canva issue for another profile was diagnosed as open and is not mixed with this repair.

## Related cases

## Evidence confidence
**Medium-high for the command, medium for cron end-to-end.** Direct command execution and cron readback are confirmed; scheduled execution/delivery remains open.
