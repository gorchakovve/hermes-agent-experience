# P-058. The PAC file existed, but Wi‑Fi auto-proxy was disabled

[Русская версия](../P-058.md)

**Evidence status:** Partially verified by the 2026-09-23 receipt. Enabling PAC was one fix, but its isolated contribution was not A/B tested.

## Time and conditions
2026-09-23, iMac Gemini web repair. A PAC file existed on disk, but the system Wi‑Fi auto-proxy setting did not use it.

## Symptoms
Applications did not follow the expected selective route even though the file existed.

## Observations vs actions
The operator checked Wi‑Fi proxy state separately from file existence and sing-box process; the existing PAC URL was enabled together with starting sing-box, refreshing upstream, and correcting DNS.

## Causal hypothesis
PAC-on-disk was not applied because Wi‑Fi auto-proxy was disabled; but the same batch had other failure causes.

## What would not have helped
Editing PAC without checking the system switch was pointless; treating file-based PAC as the final solution was also wrong.

## What helped
It helped to check three layers: file exists, Wi‑Fi points to it, local proxy listens and forwards to a working upstream.

## Result check
After the batch repair the route worked and Gemini `/app` returned HTTP 200; the one Wi‑Fi switch was not isolated.

## Limits
On September 24, Chromium was found not to accept `file://` PAC in the needed setup; this is an intermediate diagnostic layer.
