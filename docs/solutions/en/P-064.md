# P-064. Long Codex chats on the iMac stalled

[Русский](../P-064.md) · [Index](../../problem-index.en.md)

**Status:** unresolved/unconfirmed incident. The available note defines memory and responsibility architecture, but does not prove a fix for chat stalls.

## When and conditions
The public index places the problem on 2026-05-24 and the iMac Codex setup. The available primary note from that date describes Codex as the local supervisor and VPS Brain as the source of truth.

## Symptoms
According to the index, long Codex chats could stall around context compaction or a broken remote stream. The available note does not contain a reproduction, stderr/network event, or preserved transcript showing the stall boundary.

## Cause vs. hypothesis
Context compaction and remote-stream failure remain hypotheses. The confirmed part is an operating decision: important facts and decisions must not live only inside a long chat; they should be written to the Brain so a stalled/lost session does not lose state.

## What helped
A source-of-truth rule was established for continuity: Codex/iMac may operate locally, but durable outcomes are written to the Brain. This reduces the damage from a stuck chat, but it does not repair the Codex runtime itself.

## Verification
There is no acceptance test showing that a long session no longer stalls after a fix. This is therefore a conservative workaround, not a confirmed technical repair.

## What is needed to close it
Required evidence: Codex version, approximate context size, compaction signal, network/stderr event, and a controlled long-session test after a specific runtime change.

## Related cases
Use this case only as a source-of-truth discipline example; it should not claim a technical Codex runtime repair.

## Basis
2026-05-24 decision about iMac Codex and the Brain. No direct stall log or targeted post-fix verification has been found.
