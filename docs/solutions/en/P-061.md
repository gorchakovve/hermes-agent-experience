# P-061. DNS stalled when AmneziaVPN and a local proxy were combined

[Русский](../P-061.md) · [Index](../../problem-index.en.md)

**Status:** partially confirmed repair. Google AI access was restored on the incident date, but DNS was not isolated as the only root cause.

## When and conditions
2026-09-23, an iMac using AmneziaVPN plus a local sing-box/PAC route for selected Google AI traffic.

## Symptoms
The browser route to Gemini was unreliable: the local SOCKS/PAC path did not provide a stable exit, and the selected Google AI upstream could not be resolved through the previous DNS arrangement.

## Cause vs. hypothesis
Three factors were confirmed together: the local sing-box agent was not loaded, the saved upstream no longer resolved, and sing-box DNS had to be aligned with the macOS system resolver while AmneziaVPN was active. This is therefore a combined network failure, not a proven DNS-only bug.

## What helped
sing-box was loaded, the upstream was refreshed with user consent, sing-box DNS was moved to the macOS system resolver, and the existing Wi-Fi PAC was re-enabled. The VPN/VPS layer was not changed in this step.

## Verification
The local SOCKS listener came up, Google AI traffic used the selected outbound, and `gemini.google.com/app` returned HTTP 200 without an unsupported-country marker on the public page.

## What is not proven
There was no separate DNS-only A/B test with resolver timing. The Google AI route changed later, so this case should not be projected onto the current server-side routing design.
