# P-012. Cloudflare Access blocked HTTP-01 certificate renewal

**Русский:** [P-012](../P-012.md)

**Status:** confirmed result. Certificates renewed after a narrow bypass rule; normal routes remained behind Access.

## Timing and conditions
The case was recorded on 2026-08-04 for two public hostnames where web interfaces were protected by Cloudflare Access and Let’s Encrypt used HTTP-01 challenges. DNS/proxy routing worked for users, but the ACME validator needed unauthenticated access to a special path.

## Symptoms
Certificate renewal failed. From the outside this could look like a certbot, reverse-proxy, or DNS problem. The actual issue was that normal user access was intentionally protected by Access, and the same policy also covered `/.well-known/acme-challenge/*`.

## Cause
Confirmed cause: Cloudflare Access required authentication where ACME HTTP-01 must receive a plain HTTP/HTTPS response without interactive login. Let’s Encrypt cannot pass an Access policy as a user.

## Agent/user distinction
The user needed renewal restored without exposing admin interfaces. The agent’s job was to open only the ACME challenge path for the required hostnames, not disable Access globally.

## What did not help or was unsafe
- Temporarily disabling Access for the whole site: that exposes more surface than needed.
- Retrying certificate issuance without changing access policy: the validator will hit the same auth wall.
- Concluding “DNS is broken” from HTTP-01 failure alone: DNS was not the sufficient explanation here.

## What worked
1. Confirmed the challenge path was covered by Access.
2. Added a minimal bypass only for `/.well-known/acme-challenge/*` on the required hostnames.
3. Left ordinary routes protected.
4. Re-ran renewal.
5. Checked certificate expiry and verified protected pages still required Access.

Safe generic checks:

```bash
curl -i https://example.com/.well-known/acme-challenge/test-token
certbot renew --dry-run
openssl s_client -connect example.com:443 -servername example.com </dev/null 2>/dev/null | openssl x509 -noout -dates
```

## Verification
Both certificates renewed successfully, the new expiry date was recorded, and ordinary routes did not become public. This verifies the targeted HTTP-01-behind-Access fix.

## Limits
If policy forbids even a narrow HTTP-01 bypass, use DNS-01. In Cloudflare, check rule order and scope: a broader policy can override a targeted exception.

## Evidence and confidence
Evidence: 2026-08-04 VPS full-remediation receipt. Confidence: high for cause and result; medium for transfer to other WAF/Access setups.
