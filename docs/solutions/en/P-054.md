# P-054. OpenClaw Desktop repeated a stale `Approve Mac` request

[Русская версия](../P-054.md)

**Evidence status:** Verified by 2026-07-15 maintenance receipts. The fix was Desktop-side; VPS device authorization was not reset.

## Time and conditions
2026-07-15. iMac OpenClaw Desktop 2026.6.11 was talking to VPS Gateway 2026.7.1.

## Symptoms
Desktop repeatedly showed `Approve Mac`; approve did not help. Gateway had no pending requests and saw the iMac approved/connected.

## Observations vs actions
The operator checked Gateway health, pending requests, and the approved node, made a local recovery copy, and allowed the normal Desktop updater. Pairing records/routes/MCP/permissions were not touched.

## Causal hypothesis
The old Desktop replayed a stale request ID the Gateway no longer knew: a client-side stale-approval loop, not a new access request.

## What would not have helped
Resetting devices, deleting the paired node, or manually replacing the bundle could have created a new incident.

## What helped
It helped to prove no pending request existed, then update the stale Desktop through the verified updater and restart only the app.

## Result check
After update, app and running Desktop were 2026.7.1; the same node was approved/connected; no pending requests or new unknown-request errors remained.

## Limits
If Gateway actually shows a new pending request, use a different procedure.

Basis: scoped Brain maintenance/lesson/canon records and git history in this documentation branch. Raw logs, private paths, domains/IPs, emails, secrets, and configurations are intentionally not published.
