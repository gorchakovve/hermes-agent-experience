# P-001. Two OpenClaw entry points reported different CLI and gateway versions

**Status:** confirmed for the 2026-07-15 VPS check; the origin of the old system symlink was not investigated.

**Evidence:** Primary operations note from 2026-07-15 about OpenClaw alignment; direct observation of CLI/gateway versions and service state. Raw logs, private paths, tokens, domains, and addresses are intentionally omitted.

**RU:** [`P-001.md`](../P-001.md)

## Symptoms
Different ways of invoking OpenClaw reported different versions, while the active gateway itself was healthy. This made the issue look like a failed update or a misleading CLI.

## Conditions and timing
VPS, 2026-07-15. The active gateway, operator CLI, old system wrapper/symlink, and two official plugins were checked.

## Hypothesis / root cause
The active gateway and the operator CLI were already on 2026.7.1, while an old system wrapper/symlink still pointed to 2026.6.11. Two active official plugins also lagged at 2026.6.10. There was no single canonical “OpenClaw version” until the actual runtime entry points were compared.

## Actions that worked
First identify the executable used by the systemd service and the CLI actually used by operators. Create a rollback anchor before changing anything. In the observed case, only the two active official plugins were aligned to the gateway version and only the gateway was restarted. The old system symlink was deliberately left unchanged to avoid widening the change.

## Verification
After restart, the operator CLI and gateway both reported 2026.7.1; local gateway health and adjacent service checks passed.

## Limitations
Do not claim the old system symlink was fixed: it was intentionally left as known path drift. The date and live outcome are supported by the operations note, but the earlier origin of the second entry point is not proven.
