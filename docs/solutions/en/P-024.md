# P-024. An obsolete Google AI node stopped accepting connections

**Status:** partially resolved for the iMac browser route; the VPS xray/upstream path remained a separate open item.

[Русская версия](../P-024.md)

## Symptom
On the iMac, Gemini access through the previously saved Google AI proxy stopped working. The old upstream no longer resolved or reset connections; the local SOCKS port could also be absent if the sing-box LaunchAgent was not loaded. On the VPS, the previous upstream still produced connection resets in local smokes.

## Conditions
The repair was scoped to iMac browser access to Gemini, not to the central VPS xray route. The ordinary AmneziaVPN route had to be preserved, and subscription details could not be exposed. The existing provider subscription was refreshed only after explicit user consent.

## Causes
The record separates three layers: local sing-box was not loaded; the saved Reality upstream was obsolete; the PAC file existed but Wi-Fi auto-proxy was disabled. These causes could not be collapsed into one: replacing upstream would not help if SOCKS was not listening, and enabling PAC would not revive a dead upstream.

## Actions taken
The operator loaded and verified sing-box, refreshed the subscription with consent, tested current nodes without exposing credentials, selected a working European Reality node, changed sing-box DNS to the macOS system resolver for compatibility with the active VPN, and enabled the existing Wi-Fi PAC.

## Verification
After repair, `io.sing-box` was running, the local SOCKS listener was present on loopback, the Gemini web app returned HTTP 200, and the fetched page did not contain an explicit unsupported-country marker. That confirms restored browser transport access on the iMac.

## What remained open
The VPS xray route was not changed in this operation. The Brain receipt explicitly says both VPS localhost proxy smokes still returned connection reset, and the protected service update required separate approval. Therefore this iMac repair must not be reported as a central VPS Gemini proxy repair.

## Operational lesson
Diagnose the Google AI browser route by layer: launch agent/listener, DNS/upstream, PAC/system proxy state, then the Gemini page marker. HTTP 200 without an unsupported marker is useful, but it is not a full signed-in chat smoke; NotebookLM/Gemini account scenarios need separate acceptance, as in [P-025](P-025.md).
