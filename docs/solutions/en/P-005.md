# P-005. OpenClaw updates overwrote local settings and compatibility patches

**Status:** confirmed for the 2026-07-02 recovery; long-term persistence across future updates is not proven.

**Evidence:** 2026-07-02 update note; direct observation of helper-script targets, active package repair, CLI version, health, and public guard. Raw logs, private paths, tokens, domains, and addresses are intentionally omitted.

**RU:** [`P-005.md`](../P-005.md)

## Symptoms
After replacing the package, the private proxy patch and Telegram compatibility repair had to be re-applied; the first attempt could target the inactive copy.

## Conditions and timing
VPS, 2026-07-02; OpenClaw update 2026.6.10 → 2026.6.11.

## Hypothesis / root cause
The npm package replacement restored the upstream bundle, and helper scripts initially targeted the inactive tree. The runtime therefore kept using the old active copy without the required repairs.

## Actions that worked
Retargeted the updater, post-update repair, and Telegram repair helper to the active package tree. After backup, re-applied compatibility repairs to the active copy and restarted only the gateway.

## Verification
The active CLI reported 2026.6.11; gateway health returned live; the public endpoint guard passed without failures/warnings.

## Limitations
This confirms recovery for the specific version, not a guarantee that all future package replacements preserve local changes. Always identify the active runtime and create a rollback copy before repair.
