# P-019. `Blocked hostname` after cooldown: no proven targeted fix found

**Русский:** [P-019](../P-019.md)

**Status:** unresolved from available sources. A nearby private-proxy dispatcher fix exists, but it does not prove the exact `Blocked hostname` loop after authorization cooldown.

## Timing and conditions
The index points to an around-2026-05-24 problem: OpenClaw entered a `Blocked hostname` loop after cooldown. Brain contains records about live update, private/internal hostname blocking in an inter-agent proxy path, and a later dispatcher-policy fix.

## Symptoms
The described symptom: after cooldown, the agent again hit `Blocked hostname or private/internal/special-use IP address`. That may mean a guard blocked access to a private/internal endpoint even though the route was intentionally allowed through an explicit private proxy dispatcher.

## Cause or testable hypothesis
Testable hypothesis: the resolved dispatcher policy did not carry `allowPrivateProxy` into the actual runtime path, so the guard blocked the endpoint. This hypothesis is confirmed for a found private-proxy smoke case, but not proven to be the same “after cooldown” incident.

## Agent/user distinction
The user sees a recurring block and expects repair. The agent must not disable hostname/SSRF protection globally; it must prove that this specific private route is policy-approved and that the approval reaches the dispatcher.

## What did not help or was risky
- Globally disabling SSRF/private-hostname protection.
- Treating every `Blocked hostname` as the same: some blocks are intended protection.
- Crediting the 2026-05-24 live update with fixing the cooldown loop without before/after logs.

## Known working pattern
For the confirmed neighboring private-proxy dispatcher fix, the working validation shape was:
1. Reproduce the block on a specific inter-agent smoke.
2. Inspect resolved policy and explicit private-proxy permission.
3. Fix the dispatcher path so the permission survives to runtime.
4. Repeat smokes in both directions and get exact sentinels.

## Verification
In the found dispatcher-fix record, the post-fix smoke body exactly matched the expected sentinel and the reverse route passed too. For P-019’s narrow “after cooldown” wording, no direct before/after verification was found.

## Limits
