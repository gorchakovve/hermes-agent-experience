# P-050. ARM64 Hermes Desktop did not run on an Intel iMac

**Русская версия:** [../P-050.md](../P-050.md)

## Status
**Verified on 2026-07-02; canon was updated later.** On the checked date, the official macOS DMG/app was ARM64-only for the Intel iMac, while a source-built x86_64 Hermes Desktop worked as a local lab/interface. It did not replace VPS production.

## Conditions
- Initial repair date: 2026-07-02.
- Device: Intel iMac (`x86_64`).
- Surface: Hermes Desktop macOS app, separate from VPS Hermes/Talos production.
- Actors: the official DMG/app provides a binary; the local source build creates an Intel-compatible app; launcher/profile start the backend.

## Symptoms
Two downloaded official DMGs and the installed app contained an ARM64 executable. Downloading again did not change the result because the files matched by hash.

## Cause / hypothesis
At that time, the official Hermes macOS Desktop installer was Apple-Silicon-oriented/ARM64-only. The Intel iMac could not use it as a working Desktop path. A source build for x86_64, or a future official universal/x86_64 release, was required.

## Failed sequence
1. Download the official DMG again.
2. Install the `/Applications` app.
3. Check executable architecture.
4. Get the same ARM64-only binary on an Intel host.

## Successful sequence
1. Check host and executable architecture with local system tools.
2. Compare DMG hashes to rule out a corrupted download.
3. Build Electron/Desktop from source for x86_64.
4. Locally sign the app and bind it to a separate profile/runtime and launcher.
5. Do not install a second production gateway on the iMac.
6. Add an update helper that builds from source, verifies x86_64, runs smoke, and can roll back instead of using the official DMG.

## Verification
- The two DMGs matched by SHA-256 and contained an ARM64 binary; the installed official app was also ARM64.
- The source-built app was identified as `x86_64`.
- The launcher reported Hermes Agent version and upstream revision.
- The backend from the permanent local profile reached dashboard-ready/startup-ready state.
- Later canon established the rule: update Intel Desktop only through the controlled helper, not the official DMG/in-app/blind update path.

## Limitations
- The local Intel app is a lab/interface and fallback/update substrate, not the production VPS agent.
- The official DMG did not become Intel-compatible because of the local build.
- Future updates require live verification: official support may change, and the local baseline has been updated since.

## Related cases
- [P-048](P-048.md) — both cases show why runtime/interpreter/architecture must be explicit rather than ambient default.

## Evidence confidence
**High.** Evidence includes hash/architecture checks, successful source build, launcher/version receipt, backend-ready smoke, and canon/update-policy receipts.
