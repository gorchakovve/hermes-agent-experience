# P-053. A root-owned npm cache broke the Intel Hermes Desktop update

[Русская версия](../P-053.md)

**Evidence status:** Verified by a 2026-09-25 maintenance receipt. The VPS update was checked as a no-op; the Desktop repair completed and was verified.

## Time and conditions
2026-09-25. Source-built Intel Hermes Desktop was updated separately from VPS Hermes; the VPS already matched upstream.

## Symptoms
The in-app update failed twice with exit code 1 because npm could not create a directory in a root-owned cache.

## Observations vs actions
Codex/the operator first checked VPS SHA, active services, and the API through the tunnel; no VPS update was run. Only the Intel Desktop build path was repaired.

## Causal hypothesis
The cause was local to the macOS build environment: a user updater hit a root-owned npm cache, not production Hermes.

## What would not have helped
Running the whole build with sudo, recursively chowning the whole cache, or doing a no-op VPS update would not have solved the right problem.

## What helped
A verified Intel helper with an isolated user-owned npm cache and rollback copies helped; the shared/root-owned cache was not touched.

## Result check
The build completed at the expected source SHA; the executable was x86_64; signature check passed; Desktop saw the remote backend; authenticated WebSocket stayed open.

## Limits
Dependency advisories were a separate residual risk; lockfiles/upstream dependencies were not changed by this operational repair. The later production-dependency verification is [P-088](P-088.md); the profile-backup race is [P-089](P-089.md).
