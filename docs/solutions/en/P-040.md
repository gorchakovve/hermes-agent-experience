# P-040. A systemd watcher could select an old OpenClaw binary through PATH

[Русский](../P-040.md) · [Index](../../problem-index.en.md)

**Status:** verified as part of the April handoff repair; later checks showed a separate stale system CLI, so attribution depends on date and unit.

## Conditions and symptoms

In April 2026, the Hermes → OpenClaw watcher/runner chain depended on PATH in a systemd environment. That could select the wrong `openclaw` binary, especially after updates and coexistence of global and managed CLIs. The symptom overlapped with P-039: handoff did not return the expected result.

## Cause and testable hypothesis

PATH in a service context is not the same as an interactive shell. A command that resolves to the right CLI in a terminal can resolve to an old binary in a watcher unit. The hypothesis to test: the unit should either use the intended binary explicitly or log/check the resolved path before work.

Generic safe check:

```sh
command -v openclaw
openclaw --version
# In systemd units/runners, prefer a verified absolute path or wrapper.
```

## What helped and relation to the neighboring case

In the April auto-cycle repair, the runner was pinned to a specific CLI and the obsolete local-mode launch was removed. This happened together with the result-directory and JSON-path fixes, so P-040 is one cause inside the broader P-039 incident, not a fully independent incident.

In May, a separate direct-maintenance record fixed a stale global CLI symlink without restarting the service because the live gateway already used the managed binary. A July Hermes update record concerns Hermes versions and should not be overread as historical OpenClaw PATH evidence.

## Validation and limits

The April record verifies manual `RUNNER_SMOKE_OK` and automatic `WATCHER_AUTO_OK` after CLI pinning and the other fixes. The May direct verification separately confirmed the stale system CLI was corrected and the gateway was active. Limit: for any other watcher, read that unit's service definition and resolve `command -v` inside the same environment.

## Evidence

Evidence: private records of the auto-cycle repair dated 22 April 2026 and CLI verification dated 24 May 2026. Absolute paths and raw logs are not published.
