# P-083. The first Hermes check was interrupted by a gateway restart

**Status:** the failure class was confirmed later; the specific first Hermes check has no complete public-safe before/after receipt.

[Русская версия](../P-083.md)

## Time and conditions

The index places this case around 24 May 2026: the first Hermes check was interrupted by a gateway restart, and the service definition needed an update. Later, on 20 June, a separate lesson documented the same class of error: an agent must not restart its own gateway in the middle of a reply.

## Symptoms

An audit or answer gets cut off. The process that should deliver the result to the user is restarted by its own tool call. Externally this appears as incomplete output, a lost progress/status message, or a need to rerun the check.

## Cause / hypothesis

The class root cause is self-restart mid-turn. If an agent restarts its own gateway while generating or delivering an answer, it kills the channel that should report the result. For the May Hermes event, only indirect confirmation was found; the June lesson shows the mechanism on a neighboring gateway.

## Who did what

In May, an audit confirmed Hermes gateway activity, Telegram connection, primary model response, Gemini fallback smoke, and Workspace MCP connectivity. In June, the rule was written explicitly: do not restart OpenClaw/Hermes gateway in the middle of the current turn; apply patches and restarts as separate steps.

## What failed / what helped

Running restart as an ordinary command inside an unfinished reply failed as an operating pattern. The useful pattern is: apply the change without restart, tell the user, restart as a separate step, then verify active state and smoke after recovery.

## Verification

There is evidence that after the May audit Hermes gateway and related routes were active. There is no found receipt showing the exact first interrupted check rerun fully after a specific service-definition fix. Therefore the exact May incident remains not fully closed.

## Limits and evidence provenance

The basis is private audit notes from 24 May and a self-restart lesson from 20 June 2026. Raw logs, internal unit diffs, hosts, and paths are not public. The article treats the risk class as proven, not the exact first audit as fully remediated.
