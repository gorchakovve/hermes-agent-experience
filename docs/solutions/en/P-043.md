# P-043. OpenClaw stayed silent in a Telegram group because of `NO_REPLY`

**Русская версия:** [../P-043.md](../P-043.md)

## Status
**Partially verified as of 2026-06-21.** The configuration fix was applied and read back, the gateway started, and Telegram reconnected. The source receipt did not capture a direct user-facing test message after the fix.

## Conditions
- Date: 2026-06-21.
- Surface: Talos/OpenClaw in a Telegram forum/group topic.
- Actors: the model could emit the `NO_REPLY` sentinel; the promise guard requested revision; the upper pipeline decided whether to retry/send a visible answer.

## Symptoms
For clearly reply-worthy messages, the model returned only `NO_REPLY` twice. The guard logged that a revision/forced reply was needed, but final delivery was suppressed and the user saw silence.

## Cause / hypothesis
The Telegram group route inherited the default silent-reply policy: group = allow. Under that policy the system prompt allowed `NO_REPLY`, and the downstream pipeline treated a silent answer as acceptable and did not retry, even though the guard requested revision. This is not the same failure as Telegram unsupported-message rendering.

## Failed sequence
1. A message in a forum/group topic reaches the agent.
2. The model chooses the `NO_REPLY` sentinel.
3. The guard correctly requests revision.
4. The delivery pipeline treats silent reply as allowed and ends the turn without a visible answer.

## Successful sequence
1. Check the schema/config for the OpenClaw version.
2. If the bot must answer allowed group requests, set Telegram group silent reply policy to `disallow` through the supported config mechanism.
3. Run config validation.
4. Read the value back.
5. Restart only the required gateway and test a real message in the same topic.

## Verification
The internal receipt confirms: dry-run/validation passed, the group silent policy read back as `disallow`, the gateway started, and the Telegram provider reconnected. A user-facing live reply after the change was not confirmed in the receipt.

## Limitations
- Do not apply this globally to groups where the bot is intentionally supposed to lurk.
- This is a per-surface Telegram setting for OpenClaw/Talos, not a Hermes or other-channel setting.
- Full closure requires a real message in the affected topic and a visible answer.

- [P-044](P-044.md), [P-045](P-045.md), [P-047](P-047.md) — other Telegram failures were rich-payload rendering issues, not silence.
