# P-028. A nested env reference may have broken Notion MCP authorization

**Status:** hypothesis unconfirmed; available records prove SecretRef/env hardening and other Notion issues, not a targeted nested-env fix.

[Русская версия](../P-028.md)

## Symptom
The source index associated a Notion MCP auth failure with a nested env reference. The available Brain records contain adjacent concepts — SecretRef, moving bearer tokens out of argv, env-backed Authorization headers, 403, and schema 400 — but not direct proof that a nested env reference was the cause.

## Conditions
By 2026-05-24, Talos/OpenClaw already used SecretRef/env for Notion and Supabase authorization. The healthcheck showed SecretRef env was present, yet direct MCP initialize/list-tools for Notion returned HTTP 403. In the same period, a separate Notion mutation-tool schema issue was handled by limiting to read-only tools.

## What is confirmed
The hardening pass moved the Notion MCP bearer token out of process argv into a protected environment file for the standalone service and replaced a literal bearer header in OpenClaw config with an env placeholder. After restart, the Talos gateway returned to ready. That secret-hygiene improvement is confirmed.

## What is not confirmed
I did not find a record showing that a nested env reference resolved incorrectly, that a change fixed resolution, and that Notion MCP auth smoke passed because of that change. In fact, a healthcheck with SecretRef/env present still recorded 403 for direct MCP list-tools.

## Correct classification
This public case should remain `unconfirmed`. It must not be presented as a fixed Notion auth root cause. Confirmed facts are narrower: secret hygiene improved; the Notion schema issue had a read-only workaround; Notion/Supabase 403 were later contained/disabled until smoke.

## Closure criteria
A closure record needs a minimal redacted reproduction: config fragment without secrets showing the nested env reference, the resolved header class without value, 403 before the change, the new env-reference form, then successful Notion MCP initialize/list-tools and at least one read-only page/self call. Without that, nested-env remains a hypothesis.
