# P-089. A disappearing temporary marker interrupted a Desktop profile backup

[Русский](../P-089.md) · [Index](../../problem-index.en.md)

**Status:** verified for the local update; not validated as a universal fix for other environments.

## Conditions and symptoms

On 25 September 2026, before installing a patched Hermes Desktop build on an Intel iMac, the update helper started copying its profile for rollback. A temporary update marker disappeared while the copy was in progress, and `ditto` aborted the backup. Proceeding with app replacement before completing a usable backup would have increased recovery risk.

## Cause and response

The implementer's record identifies a race between changes to a transient marker and traversal of the profile directory. They switched the local helper's profile copy to `rsync -a`, excluding **only** that transient marker. Other profile files were not excluded. The previous helper and a backup pair of the app and profile were retained for rollback. This describes another implementer's recorded actions; I did not personally observe the terminal session.

For your own installation, first establish which files are genuinely transient. Do not remove markers or the profile directory without understanding their role. A generic example with local placeholder paths is:

```sh
rsync -a --exclude='.hermes-update-in-progress' './profile/' './profile-backup/'
```

Check the backup before installing the replacement application.

## Verification and limits

The record reports a successful syntax check, status check and smoke test of the revised helper. The subsequently installed Desktop app passed signature and bundle-checksum checks, and connected to the backend. Those checks support this particular update, not a blanket claim that every backup race has been eliminated. Adapt the exclusion only to a diagnosed ephemeral file, and verify rollback readiness before removing an older backup.
