# P-042. Agent promised work without evidence

**Русская версия:** [../P-042.md](../P-042.md)

## Status
**Verified for Talos/OpenClaw as of 2026-06-15.** The runtime guard is enforced only before final answer delivery. The message-sending hook remains observe-only because that layer lacks a stable run/session identifier.

## Conditions
- Date: 2026-06-15.
- Surface: Talos/OpenClaw, Telegram/agent responses, promise guard.
- Actors: the model drafts the final answer; the guard checks promises and receipts; the delivery pipeline sends the final text.

## Symptoms
The agent could answer “I’ll do it”, “continuing”, or “I’ll send it” without launching a tool, writing a file, creating a handoff, or producing another verifiable same-turn result.

## Cause / hypothesis
A prompt rule is not a guarantee. A runtime gate is required: if the final answer promises work but the current turn has no receipt, the answer must become an honest blocker. Enforcement at message-sending time was considered unsafe because that layer lacked stable run/session correlation.

## Failed sequence
1. The user asks for an action.
2. The model promises to do it later.
3. No tool or other action runs.
4. The user receives progress theater without an artifact.

## Successful sequence
1. The guard inspects the final answer before delivery.
2. If it finds a promise and `receipts=0`, it requests a revision.
3. The final answer is rewritten as an honest `[BLOCKED]`/not-yet-started response with a concrete next step.
4. `message_sending` keeps observing/logging but does not block delivery.

## Verification
A controlled no-deliver test produced `promise=true`, `receipts=0`, `wouldRevise=true`; the final answer was rewritten into an honest blocker. Separate smokes showed that a promise with a real receipt is not blocked and the gateway remains active.

## Limitations
- The proof validates this guard behavior, not the semantic truth of every possible receipt.
- It is not proof of delivery in every Telegram topic.
- The guard did not change the model, proxy, Telegram delivery plugin, or OpenClaw architecture.

## Related cases
- [P-041](P-041.md) — inter-agent work also needs ack/resolve/close receipts.
- [P-043](P-043.md) — separate failure: silent `NO_REPLY` could suppress delivery even after a guard revision request.

## Evidence confidence
**High.** Dated internal receipts cover rollout, controlled no-deliver proof, observe smokes, and the decision not to enforce at the unsafe message-sending layer.
