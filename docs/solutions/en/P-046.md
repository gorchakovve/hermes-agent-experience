# P-046. A Telegram topic kept stale message-tool context

**Русская версия:** [../P-046.md](../P-046.md)

## Status
**Partially verified as of 2026-06-14.** A narrow reset of the specific topic session was performed safely, but no next-user-message smoke after the reset was captured, so the repair cannot be called fully verified.

## Conditions
- Date: 2026-06-14.
- Surface: Talos/OpenClaw Telegram topic after moving delivery from `message_tool` to automatic replies.
- Actors: Telegram delivery successfully sent the final answer; session state also carried stale tool context.

## Symptoms
The final answer arrived, but a visible `Message failed` bubble appeared at the same time. It looked like a Telegram delivery failure even though the main outbound send had succeeded.

## Cause / hypothesis
The session state for one Telegram topic retained old `message` tool context. After the move to automatic replies, that stale context still attempted to call a missing tool path, creating a separate error next to the successful send.

## Failed sequence
1. Delivery is moved to automatic replies.
2. The old topic session remains in pre-migration state.
3. A new answer is sent successfully.
4. The old tool context additionally tries to call the `message` tool and produces a visible failure.

## Successful sequence
1. First verify config is valid, the gateway is active, and real sending works.
2. Confirm the error is session/tool context, not Telegram auth/login.
3. Make a backup.
4. Move/archive only the affected topic-session files; do not delete broadly.
5. On the next user message, verify there is no repeated tool error.

## Verification
Before the reset, config validity, active gateway, and successful outbound send were confirmed. The specific topic-session files were moved aside with an archive suffix, not deleted. The receipt states expected next-message behavior but does not contain a post-reset smoke.

## Limitations
- A new user-message smoke in the same topic is required.
- Do not claim verified repair until the repeated `Message failed` is absent after reset.
- Do not apply this method to other topics/sessions without separate diagnosis.

## Related cases
- [P-044](P-044.md), [P-045](P-045.md), [P-047](P-047.md) — Telegram rendering failures; here the send succeeded and the error came from stale session context.

## Evidence confidence
**Medium for diagnosis, low-medium for full repair.** Logs separated successful send from stale tool lookup, but the post-reset smoke is missing.
