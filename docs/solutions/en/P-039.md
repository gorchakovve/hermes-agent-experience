# P-039. OpenClaw results were written to the wrong place and parsed with the wrong JSON path

[Русский](../P-039.md) · [Index](../../problem-index.en.md)

**Status:** verified by manual and automatic smoke tests on 22 April 2026.

## Conditions and symptoms

The automatic Hermes → Talos/OpenClaw → result-file cycle did not return the expected answer. From the user side, the handoff did not complete, even though individual services could still be alive.

## Causes and testable hypotheses

The investigation found several causes at once:

1. the runner launched OpenClaw in an obsolete local mode;
2. the result directory pointed to the wrong side of the inbox;
3. JSON parsing read `.text`, while the actual answer was deeper in the result structure;
4. the systemd environment could select an old CLI through PATH.

Because multiple changes landed together, success cannot honestly be attributed to only one patch. The acceptance criterion was end-to-end: both manual runner smoke and automatic watcher smoke must return the expected text.

## What helped

Four changes helped: remove the old local-mode launch, pin the intended CLI, correct the result directory, and parse the correct JSON path. For similar runner integrations, verify not only CLI stdout but also the actual file consumed by the next stage.

Generic JSON path check:

```sh
jq -r '.result.payloads[0].text' result.json
```

## Validation and limits

The 22 April record reports two smokes: manual result `RUNNER_SMOKE_OK` and automatic watcher result `WATCHER_AUTO_OK`. Limit: this proves the cycle worked after the combined changes; it does not isolate each patch's individual contribution.

## Evidence

Internal record “Hermes ↔ Talos auto-cycle fixed” dated 22 April 2026. Absolute private result directories and raw task files are omitted.
