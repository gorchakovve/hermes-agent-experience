# P-021. `hermes doctor` falsely reported a Gemini failure

**Status:** partially confirmed: the false diagnostic interpretation is proven, but a doctor-command fix is not confirmed in the available records.

[Русская версия](../P-021.md)

## Symptom
Hermes doctor reported Gemini as failing, with output that looked like an invalid key or HTTP 400. The actual Hermes route through the scoped SOCKS proxy still worked: the proxied model smoke returned the expected result, and independent checks showed that the proxy listener was alive.

## Conditions
The case belongs to a VPS Hermes installation with a dedicated local SOCKS path for Gemini. Talos/OpenClaw used a separate local HTTP path for Google fallback. That split matters because the diagnostic CLI, runtime provider, and proxy smoke were not the same transport test.

## Cause or working hypothesis
The confirmed issue is route mismatch. Doctor/local infer checks did not exercise the same transport as the real Hermes runtime using the proxy. Therefore a doctor FAIL proved a diagnostic or provider-transport problem, not necessarily an invalid Gemini key and not a reason to rotate secrets immediately.

## Actions taken
Operators separated the questions: whether the local proxy was listening, whether a request could reach a Google endpoint through the proxy, whether the real Hermes model smoke worked, and what exactly doctor reported. Brain records show the proxy and model smoke were alive; the PVA audit explicitly kept the Hermes Gemini doctor warning as a known yellow item while scoped-proxy Gemini smoke passed.

## Verification
The verified result is limited: the proxied runtime request worked, and the diagnostic warning was classified as false-positive/incomplete. I did not find a record proving that `hermes doctor` itself was patched and later returned a green Gemini status.

## Operational lesson
When this symptom recurs, compare the doctor route with the runtime route first. Test the proxy and a minimal Gemini request without printing secrets; do not rotate the key or disturb the working proxy chain only because doctor says FAIL. This case relates to [P-022](P-022.md), where direct VPS regional access to Google APIs really was blocked, and [P-025](P-025.md), where Google AI reserve paths required separate acceptance.

## Limitations
Status remains partial: symptoms and the false interpretation are confirmed, but the exact doctor code defect and final green doctor smoke are not confirmed in the available public-safe records. Raw logs, keys, and internal configs are intentionally omitted.
