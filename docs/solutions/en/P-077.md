# P-077. Large skills transferred worse between agents

**Status:** partially confirmed as a quality/portability class, not as one closed user incident. The bulk audit found no hard blockers or oversized blockers, but left substantial quality debt.

**Русская версия:** [P-077](../P-077.md)

## Timeframe and conditions
The key closure report is dated 2026-06-20. The runtime skill library and cross-agent/ecosystem portability were audited, with external skill patterns treated as evidence rather than material to copy verbatim.

## Symptoms
Large or poorly structured skills are harder to discover, export and apply: weak triggers, missing negative triggers, missing pitfalls, unreferenced support files, and flat-export name/directory mismatches. These do not always break loading, but reduce discoverability and transfer reliability.

## Confirmed cause vs hypothesis
Confirmed: the active audit found 109 active skills with no hard content blockers and no oversized `SKILL.md` over 100k chars, but the strict rubric found debts: missing eval prompts, missing negative triggers, weak descriptions, missing pitfalls/verification/when-to-use sections, support files not referenced, and several flat-export mismatches.

Not confirmed: one specific skill that failed Hermes→Talos transfer solely because of size. This P item should be read as a quality class, not a proven one-off repair.

## Actor attribution and actions
The operator established shared skill-quality canon, routing through the process map and a runtime authoring skill. Portability audit and external-source checker scripts were added/verified. The audit scripts were compiled and an active-only JSON audit was run.

What was not done: no mass rewrite of every skill, and no verbatim copying of external Anthropic/OpenAI/Nous materials. A prior runner had a transport crash tail; useful content was written, but the runtime crash remained a separate risk.

## Practical verification
Minimum safe audit:

```sh
python3 -m py_compile <skill-audit-script> <source-checker-script>
python3 <skill-audit-script> <skills-dir> --active-only --json
```

For a specific skill, also check: trigger starts with “Use when…”, when-to-use exists, pitfalls exist, verification exists, eval prompts exist, negative triggers exist, all support files are referenced, and exported name matches directory.

## Proof of result
On 2026-06-20 the audit scripts compiled; active audit completed operationally; hard blockers were 0 and oversized blockers were 0. Strict quality gaps remained across most of the library, so the result is “operationally safe, not quality-green.”

## Limits and open items
There is no proof that one specific large skill was fixed and then successfully transferred to every agent. For each important skill, the next step is before/after audit, eval prompts and load verification on the target agent.

## Lesson
Skill portability is not only file size. It depends on a concise trigger, explicit boundaries, negative triggers, support-file references and testable eval prompts.
