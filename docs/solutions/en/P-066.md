# P-066. A VPN handshake did not prove working traffic

[Русский](../P-066.md) · [Index](../../problem-index.en.md)

**Status:** verification lesson confirmed; the original handshake-only failure was not fully reconstructed.

## When and conditions
2026-09-18, verification of the new AmneziaWG 3.1 profile on the iMac during migration.

## Symptoms
A VPN handshake by itself could create a false success signal. The user needed actual useful traffic through the tunnel, not only a fresh handshake indicator.

## Cause vs. hypothesis
The available record does not contain a separate period where “handshake exists but traffic fails.” It shows the correct verification standard: a fresh handshake must be paired with bidirectional byte counters and an external egress test.

## What helped
The new AWG 3.1 profile was not accepted from UI status alone. The check included interface state, handshake freshness, bidirectional traffic, and public egress through the tunnel. The old AWG 2 path remained as rollback during the first stage.

## Verification
On the iMac, the new interface was up, the handshake was fresh, counters showed traffic in both directions, and the external route really used the VPN.

## What is not proven
The root cause of any previous handshake-only behavior on other devices was not established. Closing that would require route/MTU/firewall data from the failure period and a test on the specific affected client.
