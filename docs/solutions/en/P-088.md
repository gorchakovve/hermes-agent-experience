# P-088. Updating vulnerable YAML packages does not update an already installed Desktop app

[Русский](../P-088.md) · [Index](../../problem-index.en.md)

**Status:** verified for the production dependencies in the tested build; development dependencies were not fully cleared.

## Conditions and symptoms

On 25 September 2026, a dependency review of Hermes source identified production `js-yaml` and `yaml` versions requiring updates. Changing a lockfile on the VPS did not change the Desktop app already installed on an Intel iMac: it had to be rebuilt and deployed independently. A healthy Python gateway could not establish which bundled Node package versions the Desktop app contained.

## Cause and response

According to the implementer's maintenance record, they updated `js-yaml` from 4.3.1 to 4.3.2 and `yaml` from 2.8.1 to 2.8.3 in a minimal set of manifests and the lockfile. They checked the production dependency tree and audit results, ran typechecking and focused tests, and built the app in isolation. On the Intel iMac they then built from the same source revision with the same patch, installed the app, and matched the installed bundle's checksum to the verified build artifact. This is attributed to the recorded implementer; it is not a claim that I personally executed these steps.

To check **your own checkout** after updating pinned dependencies:

```sh
npm ls js-yaml yaml --omit=dev
npm audit --omit=dev
```

Do not assume a lockfile edit updates the installed app. Check its actual build and use a platform-compatible update path.

## Verification and limits

The 25 September record reports zero findings from `npm audit --omit=dev` in both the VPS checkout and installed Desktop profile. Three focused test files (nine tests), typechecking and the build passed. Signature checks and the checksum match between the installed bundle and the tested build also passed; Desktop smoke tests and backend connectivity succeeded. **This does not clear all development dependencies:** the full audit still reported six dev-only findings. After an upstream update, recheck that the fixed dependency versions have not regressed.

Related: [P-053](P-053.md) covers npm-cache permissions during an earlier build, and [P-089](P-089.md) covers the backup race in the same update window.

## Evidence

Implementer's technical maintenance receipt dated 25 September 2026, recording audit, test, build, and installed-artifact checks. Internal paths, configuration and full logs are deliberately omitted.
