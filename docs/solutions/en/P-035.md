# P-035. Secrets were present in configuration and process arguments

[Русский](../P-035.md) · [Index](../../problem-index.en.md)

**Status:** verified for migration of explicit secret-bearing fields and the Notion bearer argv issue; rotation of already exposed secrets is not verified.

## Conditions and symptoms

During the May audit, some secret values were found in OpenClaw JSON configuration, and a separate bearer for a local MCP service was passed through process argv. These are two different exposure channels: files with wrong handling, and process lists/startup logs.

## Cause and testable hypothesis

The problem was not the integrations themselves, but how secrets were stored and passed. A valid fix should remove values from readable/public surfaces and leave only environment references or private env files.

Generic validation pattern:

```sh
# Confirm config contains references, not values.
# Confirm private env-file permissions.
# Confirm ExecStart/argv does not contain bearer/token values.
# Then run lint/security audit and a health smoke.
```

## What helped and what was not done

Four secret-bearing fields were moved to env SecretRef markers, file permissions were tightened, and the Notion bearer was moved out of startup arguments into a private EnvironmentFile. The first migration deliberately did not restart the gateway; a nearby maintenance record later confirmed active gateway/service health.

What was not done: this was not secret rotation. If a secret was already present in logs, argv or shell history, a separate provider-side rotation task is needed.

## Validation and limits

The records report no remaining plaintext-secret findings from config lint, a security audit with 0 critical and 0 warnings, a successful bearer-auth Notion health check, and an active gateway. Limit: old values may already have been exposed before migration, and current env files must not be quoted or published.

## Evidence

Internal records: “Talos/OpenClaw plaintext secrets config fix”, “Agent Stack Hardening Pass” and a direct maintenance savepoint from 24 May 2026. Private file paths, token names with values, values and raw logs are omitted.
