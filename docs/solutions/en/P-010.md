# P-010. Caches and backups filled the VPS disk

**Status:** confirmed by the 2026-08-04 cleanup note.

**Evidence:** MAINTENANCE note from 2026-08-04; direct before/after filesystem numbers, retained backup list, and post-cleanup smoke/guard checks. Raw logs, private paths, tokens, domains, and addresses are intentionally omitted.

**RU:** [`P-010.md`](../P-010.md)

## Symptoms
The root filesystem was 86% full: 65 GB used, 11 GB free.

## Conditions and timing
VPS, 2026-08-04; weekly archives, pre-update backups, build/browser/model caches, package-manager caches, rotated logs, Atop logs, and inactive Snap revisions had accumulated.

## Hypothesis / root cause
Not one runaway file, but several classes of rebuildable or obsolete data. Some recovery archives and active state still had to be retained.

## Actions that worked
Deleted excess archives/backups only after separating the latest verified recovery copies and active state. Cleaned rebuildable caches, package-manager caches, stale temp/log data, and inactive Snap revisions. Set retention for Snap and the system journal.

## Verification
After cleanup: 41 GB used, 35 GB free, 54% usage; about 24 GB reclaimed. Stack smoke without model passed, and guard invariants passed.

## Limitations
Do not delete backups by glob without checking format and restore value: one retained recovery copy had a misleading extension. The public MCP endpoint and a separate WS probe retained pre-existing warnings; cleanup did not fix them.
