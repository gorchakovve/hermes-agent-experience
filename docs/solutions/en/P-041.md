# P-041. Inter-agent handoff lost acknowledgement or duplicated work

**Русская версия:** [../P-041.md](../P-041.md)

## Status
**Verified for the repaired path as of 2026-06-21.** Both Hermes↔Talos/OpenClaw directions were smoke-tested, including file fallback while the HTTP bridge was down and refusal of a repeated closed task ID. Historical tasks from before enforcement are not automatically considered closed.

## Conditions
- Incident/repair date: 2026-06-21.
- Surface: Hermes↔Talos/OpenClaw inter-agent HTTP bridge plus Brain inbox file fallback.
- Actors: the sender creates a task; bridge/file watcher delivers it; the receiver runner executes it; the ledger records lifecycle state.

## Symptoms
File-based handoff could leave a loop open, reuse a task ID, or start a runner from an invalid inbox file. Transport existed, but transport alone did not prove that the receiver saw, acknowledged, and closed the item with either a result or a blocker.

## Cause / hypothesis
Before the repair there was no mandatory single lifecycle ledger and no strict protocol-v1 validation before runner launch. A watcher could therefore react to junk, while task closure depended on scattered transport statuses.

## Failed sequence
1. An agent sent a task via bridge or fallback.
2. A watcher observed a file in the inbox.
3. Without strict validation, the file could be treated as work.
4. Repeated or unresolved task IDs lacked a strong terminal state.

## Successful sequence
1. Use one sender and one task ID.
2. Record ledger events: `send → received → ack → accepted → resolved/blocked → closed`.
3. Validate protocol-v1 before starting any runner.
4. Quarantine invalid files without executing them.
5. Refuse a repeated closed ID unless an operator explicitly forces an exception.
6. Test bridge-down fallback separately, then restore the bridge.

## Verification
- Hermes→Talos and Talos→Hermes smokes reached `closed`.
- An invalid task file was quarantined and did not launch the runner.
- Reuse of a closed task ID was rejected.
- With the bridge stopped, fallback wrote a valid task, the watcher processed it, the ledger reached `closed`, and the bridge was restored.
- The open-loop report had no unresolved real loops; one quarantine smoke artifact was intentionally left as evidence.

## Limitations
- The repair does not prove all pre-enforcement handoffs were resolved.
- Transport warnings after useful stdout were classified separately; that is not the same failure as an unclosed lifecycle.
- Raw paths, logs, addresses, and configuration are not published.
