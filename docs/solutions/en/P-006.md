# P-006. Desktop and VPS OpenClaw versions diverged

**Status:** confirmed by the 2026-07-15 Desktop recovery note.

**Evidence:** MAINTENANCE notes from 2026-07-15: version alignment and stale Desktop pairing recovery; direct observations of VPS pending requests, node approval/connection, gateway logs, and app version. Raw logs, private paths, tokens, domains, and addresses are intentionally omitted.

**RU:** [`P-006.md`](../P-006.md)

## Symptoms
The Desktop showed a repeating Approve Mac repair modal. Pressing approve did not resolve it even though the gateway was healthy.

## Conditions and timing
iMac Desktop 2026.6.11 and VPS gateway 2026.7.1, 2026-07-15.

## Hypothesis / root cause
The VPS had no pending requests, and the iMac node was already approved/connected. Gateway logs showed approval attempts for a stale request ID. This pointed to a stale client-side approval loop, not a VPS authorization problem.

## Actions that worked
Did not remove the approved device or widen permissions. Created a local recovery copy, allowed the app to install its already downloaded verified updater payload, and restarted only the Desktop client.

## Verification
Desktop and connected node became 2026.7.1; the node remained approved/connected; no pending requests remained; no new unknown requestId pairing errors were observed.

## Limitations
A downloaded payload does not mean the app is already updated. Version skew does not explain every pairing issue, but in this case the stale request loop is supported by gateway evidence.
