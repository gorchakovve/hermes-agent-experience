# P-069. VPN peers had to be recovered after migration

[Русский](../P-069.md) · [Index](../../problem-index.en.md)

**Status:** partial result. Server peers and the iMac were verified; actual traffic on two phones was not confirmed in the record.

## When and conditions
2026-09-18, device access recovery after moving to AmneziaWG 3.1.

## Symptoms
A new server container and a working iMac did not mean that every device already had a working profile. Each client needed its own peer and its own traffic verification.

## Cause vs. hypothesis
The record does not name one root cause for every device losing access. The confirmed lesson is different: protocol migration requires per-device peer management, not a global “server is up, therefore everything is restored” assumption.

## What helped
A current rollback snapshot was retained, three independent peers were configured, new profiles were handed only to the owner, and QR/keys were not published. The old path was removed only after the new AWG3.1 path and peers had been prepared.

## Verification
The iMac tunnel and public egress were verified. For two phones, QR profiles were generated and decoded back before handoff; this checks profile syntax/content but not user traffic.

## What is not proven
Actual handshake and egress on the phones themselves are not confirmed in this record. Phone peers must not be called restored until tested on the devices.
