# P-065. AmneziaWG 2 → 3 migration required separate profiles

[Русский](../P-065.md) · [Index](../../problem-index.en.md)

**Status:** partially confirmed migration. The new AWG 3.1 path worked, but the original “incompatible parameters” error text was not found.

## When and conditions
2026-09-18, migration from AmneziaWG 2 to AmneziaWG 3.1 for the iMac, followed by peer recovery for other devices.

## Symptoms
The old and new protocol/profile generations could not be treated as a one-field replacement. The index mentions incompatible parameters, while the available records show the safer chosen path: separate container, separate listener/subnet, and new profiles.

## Cause vs. hypothesis
The exact error message is not confirmed. The confirmed engineering risk is that AWG 2 and AWG 3.1 were treated as different profile generations. Blind replacement could leave devices with a handshake but no useful traffic, or no connection at all.

## What helped
A separate AWG 3.1 path was created, a dedicated iMac profile was imported, and the old AWG 2 path was kept as rollback for the first stage. In a later recovery step, independent phone peers were created and the old container was removed after the migration path existed.

## Verification
For the iMac, the new interface came up with a fresh handshake, bidirectional traffic, and public egress through the tunnel. For two phones, QR profiles were generated and decoded back before handoff.

## What is not proven
Actual phone traffic was not verified in this record. The source error/config diff was not found, so this case should not claim a specific syntax incompatibility.
