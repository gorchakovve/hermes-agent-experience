# P-085. Google Workspace OAuth and Drive/Docs permissions required retries

**Status:** partially closed; live Workspace MCP and read-only smokes were confirmed, but a complete Docs/Drive write-scope incident was not proven.

[Русская версия](../P-085.md)

## Time and conditions

On 23–24 May 2026, Google Workspace integration was being set up for the agent stack. The work involved OAuth user credentials, Workspace MCP, a CLI/skills layer, and connection to Hermes/OpenClaw. This public article intentionally omits accounts, domains, internal endpoints, and paths.

## Symptoms

Setup required multiple passes. The initial plan around one tool/credential type drifted to Workspace MCP with OAuth user credentials. Service startup was unstable across restarts, and the two-account setup required explicit user selection in requests. The index mentions Drive/Docs scopes, but the found receipts prove read-only Workspace smokes better than a full write-scope repair.

## Cause / hypothesis

Three layers were conflated: GCP/OAuth application, credential files, and the live MCP runtime. The CLI/skills layer was also not the same thing as the production MCP service. Multi-account use required OAuth user credentials and explicit user selection.

## Who did what

The agent deployed Workspace MCP as the main live route, registered it with both agent clients, stabilized startup through the installed entrypoint, and later pinned it to localhost-only binding. Health checks and read-only checks for mail labels, Drive items, and calendar lists were run for two accounts.

## What failed / what helped

It did not help to describe the CLI as the official production path without qualification or to mix the service-account plan with the OAuth-user reality. What helped was separating terms: installed CLI/skills layer, live Workspace MCP service, OAuth user credentials, and a future service-account option as a separate security decision.

## Verification

Confirmed: Workspace MCP was healthy, local-only, registered in Hermes/OpenClaw, and read-only smokes for two accounts passed. Not confirmed: a public-safe case where a Drive/Docs write-scope denial was reproduced and then fixed with a write smoke.

## Limits and evidence provenance

The basis is private deployment/postmortem records from 23–24 May 2026. Emails, private domains, internal paths, raw commands, and config are omitted. A read-only Drive list must not be presented as proof of full Docs/Drive write access.
