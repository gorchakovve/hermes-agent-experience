# P-082. OpenClaw and Hermes initially could not run required administrative commands

**Status:** partially confirmed as an access problem; no evidence proves a full targeted closure of the original failure for both agents.

[Русская версия](../P-082.md)

## Time and conditions

This case belongs to 23–24 May 2026, when the VPS, local workstation, MCP bridges, and agent gateways were being audited. The goal was to determine what agents could actually do themselves and which actions required a password or a dedicated access rule.

## Symptoms

The agents could not reliably perform administrative actions across all nodes. One node already had broad passwordless sudo for the working user; another did not. Some operations required a narrow allow rule for specific service-management commands.

## Cause / hypothesis

Several access layers were being conflated: SSH access, MCP access, file read/write capability, and permission to run an administrative command. Having one did not imply having the others. The public index points to missing admin rights, while the available records show an access audit and targeted privilege alignment rather than a complete before/after repair of one named failure.

## Who did what

Codex checked access to the VPS, the local machine, and the reverse SSH bridge. It verified live services, MCP endpoints, and where administrative commands were available without a password. A narrow local rule was added only for a limited set of service-management commands; broad sudo was not granted.

## What failed / what helped

“Give the agents full sudo” would not have been the right fix: it expands risk and still does not identify the required operation. The useful step was access inventory: identity, SSH, MCP, sudo, and exact commands were checked separately. The safe pattern is least privilege for the specific operation plus a smoke test after the change.

## Verification

A narrow smoke was confirmed: the allowed command list could be queried without a password, and gateway/MCP endpoints were active. However, no found record shows the original failing administrative command being rerun successfully by both OpenClaw and Hermes.

## Limits and evidence provenance

The basis is private decision/maintenance records from 23–24 May 2026. Private IPs, domains, user emails, internal paths, and exact sudoers snippets are omitted. The case should not be marked fully closed without the original denial and a targeted post-change smoke.
