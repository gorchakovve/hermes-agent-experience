# P-029. Google Workspace MCP was unstable after restart

**Status:** confirmed workaround on the check date; the cached entrypoint remains fragile after updates or cache cleanup.

[Русская версия](../P-029.md)

## Symptom
Workspace MCP v1.21.0 could exit or fail to start reliably after restart with the previous launch argument combination. That broke Hermes/Talos access to Google Workspace tools even when OAuth credentials and accounts themselves could be valid.

## Conditions
On the VPS, `workspace-mcp` served Google Workspace tools for both Hermes and Talos across two accounts. The important requirement was to preserve the streamable HTTP endpoint and not confuse service startup with account-specific OAuth state.

## Cause or accepted workaround
The record does not isolate one root cause for the old launch failure. Instead, operators selected a stable startup path through the actually installed Python entrypoint for Workspace MCP v1.21.0, with `--single-user`, `streamable-http`, and `--tool-tier complete`. Brain canon explicitly notes that a cache/installed-package entrypoint is fragile after cache cleanup or package update.

## Actions taken
After a backup, the unit/service was pinned to the installed entrypoint and explicit launch arguments. The service was restarted and then checked via health/MCP initialize and tool discovery. A later hardening record additionally restricted the listen address to loopback; see [P-030](P-030.md).

## Verification
Workspace MCP was active, its health endpoint was healthy, and MCP initialize/list-tools returned 75 tools. End-to-end checks confirmed access to two Workspace accounts without publishing personal data in the public case. Later registries describe the service as active, localhost-bound, with expected Workspace tools.

## Limitations
The workaround does not prove why the old argument combination failed. It also depends on the installed package path: after uv/cache cleanup or package update, the service may need its entrypoint refreshed. Future OAuth/keyring errors should not automatically be attributed to this startup bug.

## Operational lesson
For restart instability, separate service startup, HTTP health, MCP initialize/list-tools, and account-level read smoke. A successful tool list does not prove every API scope, but it does prove the server process and tool registry are up.
