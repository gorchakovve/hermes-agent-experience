# P-085. Авторизация Google Workspace и права Drive/Docs требовали повторных попыток

**Статус:** частично закрыто; live Workspace MCP и read-only проверки подтверждены, но полный incident с правами записи Docs/Drive не доказан.

[English version](en/P-085.md)

## Когда и при каких условиях

23–24 мая 2026 года настраивалась интеграция Google Workspace для агентского стека. В работу входили OAuth user credentials, Workspace MCP, навыки/CLI-слой и подключение к Hermes/OpenClaw. Публичная статья намеренно не называет аккаунты, домены, внутренние endpoints и пути.

## Симптомы

Настройка заняла несколько проходов: первоначальный план через один инструмент или тип учётных данных сместился к Workspace MCP с пользовательскими OAuth-учётными данными. При рестартах возникали проблемы стабильности сервиса, а для двух аккаунтов требовалось явно указывать нужного пользователя. Индекс отдельно упоминает scopes Drive/Docs, но найденные подтверждения лучше доказывают read-only проверки Workspace, чем полный ремонт прав записи.

## Причина / гипотеза

Смешались три слоя: GCP/OAuth application, файлы учётных данных и live MCP runtime. Кроме того, CLI/skills-слой не равен production MCP service. Для многоаккаунтного режима требовались пользовательские OAuth-учётные данные и явный выбор пользователя в запросах.

## Кто что сделал

Агент развернул Workspace MCP как основной live-маршрут, зарегистрировал его в обоих агентских клиентах, стабилизировал запуск через установленный entrypoint и позже закрепил localhost-only bind. Были проведены health checks и read-only проверки Gmail labels, Drive items и Calendar lists для двух аккаунтов.

## Что не помогло / что помогло

Не помогло называть CLI «официальным production-путём» без оговорок и смешивать план с service account с фактом пользовательского OAuth. Помогло разделить термины: установленный CLI/skills layer, live Workspace MCP service, OAuth user credentials и будущая service-account опция как отдельное security decision.

## Проверка результата

Подтверждено: Workspace MCP был healthy, доступен локально, зарегистрирован в Hermes/OpenClaw, read-only проверки для двух аккаунтов прошли. Не подтверждено: отдельный публично-безопасный кейс, где отказ Drive/Docs write-scope был воспроизведён и затем исправлен с проверкой записи.

## Ограничения и происхождение доказательств

Основание — private deployment/postmortem records от 23–24 мая 2026 года. Из статьи удалены e-mail, private domain, internal paths, raw commands и конфигурация. Не следует выдавать read-only Drive list за доказательство полного Docs/Drive write access.
