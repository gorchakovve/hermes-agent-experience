# P-007. Gateway активен, но Telegram перестал отвечать

**Статус:** частичное восстановление подтверждено; фактический ответ на пользовательское Telegram-сообщение в записи не зафиксирован.

**Основание:** MAINTENANCE-запись от 2026-06-13; прямые наблюдения состояния сервиса, gateway logs и CLI model smoke. Сырые журналы, приватные пути, токены, домены и адреса не публикуются.

**EN:** [`P-007.md`](en/P-007.md)

## Симптомы
Hermes выглядел active, но Telegram не отвечал. Последний workflow завершился drain timeout через 180 секунд и пустым ответом.

## Условия и время
Linux VPS, systemd, Hermes Agent v0.16.0 / 2026.6.5, 2026-06-13 MSK / 2026-06-12 UTC.

## Гипотеза / причина
Модельный CLI smoke работал, значит model path был жив. Сбой находился в устаревшем слое Telegram/gateway после сценария interrupted/restart. Первопричина зависшего drain не установлена.

## Что сработало
После проверки, что активного пользовательского действия нет, перезапустили только hermes-gateway.service. Старый процесс был завершён systemd по stop timeout. Talos/OpenClaw, MCP, proxy и соседние сервисы не перезапускали.

## Проверка результата
Сервис стал active; лог показал Telegram polling и running gateway; post-restart CLI smoke вернул ожидаемый ответ.

## Ограничения
Это восстановление слоя на момент проверки, а не доказанное устранение причины drain timeout. Без записи реального Telegram reply нельзя утверждать полный end-to-end-восстановление.
