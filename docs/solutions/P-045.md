# P-045. Telegram progress card показывался как неподдерживаемое сообщение

**English:** [P-045](en/P-045.md)

## Статус
**Частично подтверждено на 2026-06-20.** Progress-draft gate был закрыт, а дополнительные rich send/edit-пути позже найдены и закрыты серверными проверками. Скриншот или визуальное подтверждение конкретного клиента после всех правок в receipt отсутствует.

## Условия
- Дата: 2026-06-20.
- Контур: Talos/OpenClaw → Telegram macOS во время tool calls и slash/system replies.
- Участники: tool runner создаёт progress events; OpenClaw streaming/Telegram delivery строит preview/progress payload; Telegram client его рендерит.

## Симптомы
Во время tool calls появлялись unsupported-карточки progress draft, хотя прежнее plain-text исправление сообщало `already patched`. Позже похожий unsupported block появился на системном ответе или ответе на slash-command, не связанном с tool progress.

## Причина / гипотеза
Plain text chat path был покрыт, но для инструментов существовал отдельный rich/progress-draft path. Кроме того, самоперезапуск gateway во время tool call мог оставить осиротевшую progress card. Позже обнаружились ещё общие command/system send и streaming-preview пути.

## Неудачная последовательность
1. Оператор видит unsupported block.
2. Запускается старое исправление, которое проверяет только text send/edit path.
3. Скрипт честно отвечает `already patched` для своего узкого scope.
4. Отдельный progress или system/preview path продолжает отправлять rich payload.

## Успешная последовательность
1. Разделить text send/edit, progress drafts, command/system replies и streaming preview как разные пути.
2. Не считать идемпотентный `already patched` доказательством покрытия всех путей.
3. Отключить tool-call progress drafts до доказанной совместимости клиента.
4. Найти и перевести оставшиеся Telegram rich send/edit места вызова на plain Bot API.
5. Обновить post-update helper и проверить его идемпотентность.
6. Перезапустить только OpenClaw gateway после syntax/config checks.

## Проверка результата
- Script syntax и Node syntax прошли.
- Runtime import test для progress gate вернул `false` для тестовых tool names.
- Config validate прошёл, gateway active, Telegram provider переподключился.
- Последующий полный проход по исходникам не нашёл прежние Telegram rich маркеры мест вызова; helper повторно отработал идемпотентно.

## Ограничения
- Нет финального подтверждения скриншотом после всех исправлений.
- Bundle names и места вызова меняются между версиями, поэтому исправление должно быть повторяемым и проверяемым после обновлений.
- Отдельная проблема self-restart-mid-turn не исправляется простым plain-text patch.

## Связанные случаи
- [P-044](P-044.md) — первое plain text исправление покрыло только обычный text path.
- [P-047](P-047.md) — общий plain compatibility baseline для Hermes/Talos.

## Уверенность доказательств
**Средне-высокая для серверного покрытия, средняя для пользовательского рендера.** Есть runtime import, syntax/config checks, service health и полный проход по исходникам, но нет клиентского скриншота после исправления.
