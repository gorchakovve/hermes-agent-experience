# P-053. Root-owned npm cache сорвал обновление Intel Hermes Desktop

[English version](en/P-053.md)

**Статус доказательств:** подтверждено записью о техобслуживании от 2026-09-25. Обновление VPS было проверено как no-op; ремонт Desktop завершился и был проверен.

## Когда и в каких условиях
2026-09-25. Intel Hermes Desktop, собранный из исходников, обновлялся отдельно от VPS Hermes; VPS уже совпадал с upstream.

## Симптомы
Встроенное обновление дважды падало с кодом 1: npm не мог создать каталог в кэше, принадлежавшем root.

## Разделение наблюдений и действий
Codex/оператор сначала проверил SHA на VPS, активные службы и API через туннель; обновление VPS не запускали. Ремонт ограничили путём сборки Intel Desktop.

## Причинная гипотеза
Причина была локальной для среды сборки macOS: пользовательский updater упирался в root-owned npm cache, а не в рабочий Hermes на VPS.

## Что не сработало бы
Не помогли бы сборка всего приложения через sudo, рекурсивный chown всего кэша или повторное no-op обновление VPS.

## Что помогло
Помог проверенный Intel helper с отдельным npm-кэшем, принадлежащим пользователю, и резервными копиями для отката; общий/root-owned кэш не трогали.

## Проверка результата
Сборка завершилась на ожидаемом SHA исходников; исполняемый файл был x86_64; проверка подписи прошла; Desktop увидел удалённую серверную часть; авторизованный WebSocket остался открытым.

## Ограничения
Предупреждения о зависимостях оставались отдельным остаточным риском; lockfile и upstream-зависимости в рамках этого операционного ремонта не менялись. Поздняя адресная проверка production-зависимостей описана в [P-088](P-088.md), а гонка при создании резервной копии профиля — в [P-089](P-089.md).
