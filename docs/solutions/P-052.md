# P-052. Ошибка 401 в Desktop оказалась истёкшим Codex OAuth на VPS

[English version](en/P-052.md)

**Статус доказательств:** подтверждено записью о техобслуживании от 2026-09-24. Исправление проверено живыми контрольными тестами; следующий refresh оставался будущим риском.

## Когда и в каких условиях
2026-09-24. Hermes Desktop на Intel iMac подключался к маршруту openai-codex, обслуживаемому через VPS. Предыдущий день уже показал, что туннель и удалённый интерфейс могут работать.

## Симптомы
Desktop показывал `HTTP 401: Provided authentication token is expired`. Это выглядело как проблема входа в Desktop, но ошибка приходила из модельного маршрута на VPS.

## Разделение наблюдений и действий
Оператор отдельно проверил удалённый режим Desktop, туннель и состояние серверной части, затем — серверные события авторизации. Владелец участвовал только в интерактивном OAuth через device code, где это было необходимо. Talos/OpenClaw не переводили на этот OAuth, и его файлы авторизации не менялись.

## Причинная гипотеза
Подтверждённая причина — старый refresh token Hermes Codex уже был использован другим клиентом или другим путём и стал окончательно недействительным. Это не было отказом туннеля и не было поломкой бинарника Desktop.

## Что не сработало бы
Перезапускать туннель, переустанавливать Desktop или переносить один refresh token между агентами опасно: это скрывает проблему единственного владельца токена и может снова сделать учётные данные недействительными.

## Что помогло
Для Hermes создали новые OAuth-учётные данные через интерактивный device-code flow, проверили отсутствие активных задач, перезапустили только зависимые службы Hermes и удалили только доказанно недействительные старые учётные данные.

## Проверка результата
Две контрольные проверки основной модели вернули ожидаемые строки. После них не появилось новых ошибок 401, `token expired` или `reused token`; gateway, Telegram, туннельная точка Desktop и готовность Desktop были проверены отдельно.

## Ограничения
Токены и сырое состояние авторизации не публикуются. Проверка доказывает состояние на дату ремонта, но не гарантирует бессрочную валидность OAuth и не исключает будущий случай повторного использования токена.

## Основание
Основание: ограниченные по области записи Brain о техобслуживании, уроках и каноне, а также история git этой ветки документации. Сырые журналы, приватные пути, домены/IP, email, секреты и конфигурации намеренно не публикуются.
