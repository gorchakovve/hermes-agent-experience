# P-040. Systemd watcher мог выбрать старый OpenClaw через PATH

[English](en/P-040.md) · [Индекс](../problem-index.md)

**Статус:** подтверждено как часть апрельского исправления handoff; поздние проверки показывали отдельный stale system CLI, который нужно оценивать по дате и unit.

## Условия и симптомы

В апреле 2026 года цепочка watcher/runner Hermes → OpenClaw зависела от PATH в systemd environment. Из-за этого мог выбираться не тот `openclaw` binary, особенно после обновлений и при параллельном существовании глобального и managed CLI. Симптом пересекался с P-039: handoff не возвращал ожидаемый результат.

## Причина и проверяемая гипотеза

PATH в service context не равен интерактивному shell. Команда, которая в терминале запускает правильный CLI, в watcher unit может найти старый бинарник. Проверяемая гипотеза: unit должен указывать ожидаемый binary явно или печатать/проверять resolved path перед работой.

Общий безопасный пример:

```sh
command -v openclaw
openclaw --version
# В systemd unit/runner предпочитайте проверенный абсолютный путь или wrapper.
```

## Что помогло и связь с соседним случаем

В апрельском auto-cycle fix runner закрепили на конкретный CLI и убрали устаревший local-mode launch. Это шло вместе с исправлением result directory и JSON path, поэтому P-040 — отдельная причина в общей аварии P-039, а не полностью независимый инцидент.

В мае отдельная direct-maintenance запись исправила stale global CLI symlink без рестарта сервиса, потому что live gateway уже использовал managed binary. В июле update-запись показывала версию Hermes, а не обязательно решала исторический вопрос OpenClaw PATH.

## Проверка и ограничения

Апрельская запись подтверждает ручной `RUNNER_SMOKE_OK` и автоматический `WATCHER_AUTO_OK` после закрепления CLI и остальных правок. Майская direct verification отдельно подтвердила актуализацию stale system CLI и active gateway. Ограничение: если у другого watcher другой unit или дата, нужно читать именно его service definition и `command -v` внутри того же окружения.

## Основание

Основание: закрытые записи об исправлении auto-cycle от 2026-04-22 и о проверке CLI от 2026-05-24. Абсолютные пути и сырые журналы не публикуются.
