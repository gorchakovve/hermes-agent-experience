# P-001. Две установки OpenClaw с разными версиями CLI и gateway

**Статус:** подтверждён для проверки на VPS 2026-07-15; происхождение старой системной ссылки не расследовалось.

**Основание:** первичная эксплуатационная запись от 2026-07-15 о выравнивании версий OpenClaw; прямое наблюдение версий CLI и gateway и состояния сервисов. Сырые журналы, приватные пути, токены, домены и адреса не публикуются.

**EN:** [`P-001.md`](en/P-001.md)

## Симптомы
Разные способы запуска OpenClaw показывали разные версии. При этом активный gateway работал, поэтому проблема выглядела как «обновление не применилось» или «CLI врёт».

## Условия и время
VPS, 2026-07-15. Проверялись активный gateway, рабочий CLI, старый системный wrapper/symlink и два официальных плагина.

## Гипотеза / причина
Активный gateway и рабочий CLI уже были на версии 2026.7.1, а старый системный wrapper/symlink оставался на 2026.6.11. Кроме того, два активных официальных плагина отставали и были на 2026.6.10. Это была не единая «версия OpenClaw», а несколько точек входа с разным состоянием обновления.

## Что сработало
Сначала установили, какой бинарный файл фактически запускает systemd-сервис и каким CLI пользуются операторы. Перед изменениями сделали rollback anchor. Затем выровняли только два активных официальных плагина до версии gateway и перезапустили только gateway. Старую системную ссылку не трогали, чтобы не расширять область изменений.

## Проверка результата
После перезапуска рабочий CLI и gateway сообщали 2026.7.1; локальный health gateway и соседние сервисные проверки проходили.

## Ограничения
Старую системную ссылку нельзя считать исправленной: её осознанно оставили как дрейф пути (path drift). Дата и исход подтверждены эксплуатационной записью, но ранняя история появления второй точки входа не доказана.
