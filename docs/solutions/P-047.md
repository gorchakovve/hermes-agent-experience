# P-047. Форматирование Telegram потребовало исправления обоих агентов

**English:** [P-047](en/P-047.md)

## Статус
**Подтверждено серверными smoke-проверками на 2026-06-18.** Talos/OpenClaw и Hermes переведены на Telegram-доставку, совместимую с plain text, оба gateway активны. Полное визуальное подтверждение на всех клиентах не заявляется.

## Условия
- Дата: 2026-06-18.
- Контур: Talos/OpenClaw и Hermes, оба отправляют сообщения в Telegram.
- Участники: у двух agent runtime разные Telegram adapters; исправление одного runtime не покрывает второй.

## Симптомы
После plain-send исправления только для Talos пользователь всё ещё видел Telegram unsupported/update blocks, теперь уже в ответах обоих агентов.

## Причина / гипотеза
Talos text send был частично переведён на plain, но оставались preview/final rich-edit capabilities и rich edit path. У Hermes был отдельный Telegram adapter, который мог использовать Bot API rich messages/drafts независимо от OpenClaw.

## Неудачная последовательность
1. Исправляется только Talos text send.
2. Talos пути edit/preview остаются с поддержкой rich.
3. Hermes вообще не затронут исправлением Talos.
4. Пользователь продолжает видеть unsupported blocks и у Talos, и у Hermes.

## Успешная последовательность
1. Сделать backup обоих runtime.
2. Для Talos/OpenClaw принудительно включить plain send/edit и отключить live preview/final/progress/rich capabilities.
3. Для Hermes отключить Telegram rich gate, чтобы он не использовал Bot API rich delivery.
4. Встроить общее исправление в post-update helper.
5. Проверить Node/Python syntax, config validate, затем перезапустить только затронутые gateways.
6. Выполнить реальные send smoke-проверки от обоих агентов.

## Проверка результата
- Node syntax для OpenClaw и Python compile для Hermes прошли.
- OpenClaw config validate прошёл.
- Оба gateway стали active после restart.
- Talos real-agent smoke дошёл как plain text operation.
- Hermes send smoke дошёл с intent literal markdown/plain text.
- Post-update helper подтвердил наличие маркеров совместимости.

## Ограничения
- Это серверная send/log smoke-проверка, а не доказательство скриншотом на каждом клиенте.
- Более поздние версии пакетов могут переименовать bundle files или добавить новые пути; исправление нужно запускать после обновлений.
- P-045 показал, что пути tool progress/system могут быть отдельными даже после этого baseline.

## Связанные случаи
- [P-044](P-044.md) — первый проход только для Talos.
- [P-045](P-045.md) — пробелы в путях progress/system после baseline.

## Уверенность доказательств
**Высокая для серверной доставки, средняя для полного клиентского UX.** Есть compile/syntax/config checks, service health и send smoke-проверки от двух агентов; нет полного визуального подтверждения на всех Telegram-клиентах.
