# P-048. Дайджест Seeker запускался системным Python без зависимости

**English:** [P-048](en/P-048.md)

## Статус
**Частично подтверждено на 2026-09-26.** Команда cron исправлена на Python из проектного venv и успешно выполнена напрямую. Следующий плановый cron run и доставка через нижестоящий pipeline ещё не подтверждены в receipt.

## Условия
- Дата: 2026-09-26.
- Контур: Seeker Invest daily digest как Hermes cron job, Python-проект с `.venv` и зависимостью PyYAML.
- Участники: cron запускает команду; Python interpreter импортирует зависимости; digest script формирует результат.

## Симптомы
Cron использовал относительный скрипт и ambient-интерпретатор и падал на импорте `yaml`, хотя проектная зависимость была описана и установлена в виртуальном окружении.

## Причина / гипотеза
Планировщик запускал не тот interpreter. В проектном `.venv` импорт `yaml` работал, а ambient/system Python не имел PyYAML.

## Неудачная последовательность
1. Cron запускает script без явного Python из проектного venv.
2. Shell или среда выбирает ambient-интерпретатор.
3. Import `yaml` падает.
4. Digest не формируется, несмотря на корректную зависимость в проекте.

## Успешная последовательность
1. Проверить импорт зависимости в ambient Python и в проектном venv.
2. Не менять расписание, права, источники или delivery policy.
3. В существующем cron job заменить только command на абсолютный путь к `.venv/bin/python` плюс тот же script и аргументы.
4. Запустить точную команду напрямую.
5. Прочитать cron job обратно и убедиться, что schedule и ограничения не изменились.
6. После следующего scheduled run проверить end-to-end доставку.

## Проверка результата
Прямой запуск точной команды из проектного venv завершился с exit 0, дал непустой вывод и пустой stderr. Readback cron job показал enabled status, прежнее расписание, venv path в prompt/command и сохранение ограничений read-only/delivery.

## Ограничения
- Первый плановый запуск после изменения не был зафиксирован.
- Нижестоящая доставка digest не подтверждена этим smoke.
- Отдельная OAuth/Canva проблема другого профиля была диагностирована как незакрытая и не смешивается с этим исправлением.

## Связанные случаи
- [P-042](P-042.md) — не заявлять доставку без receipt.

## Уверенность доказательств
**Средне-высокая для команды, средняя для cron end-to-end.** Прямой запуск команды и cron readback подтверждены; плановый запуск и доставка ещё открыты.
