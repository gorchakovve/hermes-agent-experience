# P-059. Chromium не загрузил `file://` PAC; Gemini также требовал маршрутизации static assets

[English version](en/P-059.md)

**Статус доказательств:** подтверждено записью от 2026-09-24 и пользовательским подтверждением. Исправление состояло из двух шагов; сводить всё к одному `file://` PAC нельзя.

## Когда и в каких условиях
2026-09-24, после первичного ремонта маршрутизации на iMac.

## Симптомы
Gemini открывался пустым или частично оформленным экраном; HTTP 200 для оболочки приложения ещё не означал рабочий чат.

## Разделение наблюдений и действий
Оператор сначала изменил только способ доставки PAC: перевёл его на loopback HTTP server, побайтно сохранив тот же PAC. Затем исследовал static assets и сравнил прямой VPN-маршрут с proxy-маршрутом.

## Причинная гипотеза
Были две причины: Chromium не принимал нужный `file://` PAC, а часть хостов static assets не попадала в селективный proxy-маршрут.

## Что не сработало бы
Остановиться на HTTP 200 для оболочки приложения было преждевременно; проксировать все Google hosts широким правилом было избыточно.

## Что помогло
Помогли loopback HTTP PAC server, обновлённый PAC URL для Wi‑Fi и добавление только наблюдённых asset hosts в правила PAC/sing-box.

## Проверка результата
Отдаваемый PAC побайтно совпал с исходным; основной script через SOCKS вернул HTTP 200; контрольный чат ответил «Работает.»; владелец подтвердил обычный интерфейс Chrome и ответы Gemini.

## Ограничения
HTTP PAC server стал новой локальной точкой отказа; VPS/VPN containers не менялись; бессрочная доступность не доказана.

## Основание
Основание: ограниченные по области записи Brain о техобслуживании, уроках и каноне, а также история git этой ветки документации. Сырые журналы, приватные пути, домены/IP, email, секреты и конфигурации намеренно не публикуются.
